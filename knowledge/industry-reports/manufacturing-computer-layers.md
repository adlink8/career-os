# 制造业与计算机的关系：分层、IT/OT 分界与协议速查

> 创建：2026-09-07
> 目的：回答"制造业和计算机有什么关系"，并定位本人在工业数字化链路中的位置与缺口。
> 关联：`knowledge/industry-reports/jiangsu-manufacturing-digitalization.md`

---

## 一、核心认知纠偏

**错误认知：计算机是"线上平台的大脑"。**

**正确认知：计算机是"任何需要自动处理信息的系统"的大脑。线上平台只是其中一种用法。**

工厂里的计算机形态：

| 形态 | 本质 | 跑什么 |
|------|------|--------|
| PLC | 工业计算机 + 实时 OS | 梯形图 / 结构化文本 |
| 工控机（IPC） | 加固 PC | SCADA 组态软件 |
| 边缘网关 | ARM/x86 小主机 | Linux + Docker + 采集程序 |
| MES/ERP 服务器 | 标准服务器 | 数据库 + 业务系统 |
| 工业云平台 | K8s 集群 | MQTT Broker + 时序库 + 分析 |

**一个中型工厂的计算机数量通常多于一个中型互联网公司**——只是它们大多长得不像服务器。

## 二、ISA-95 分层（自动化金字塔）

| 层 | 名称 | 归属 | 关键技术 | 本人状态 |
|----|------|------|---------|---------|
| 云 | 工业互联网平台 | IT | MQTT、时序数据库、容器、大数据分析 | **已具备** |
| L4 | 企业层 ERP / PLM | IT | SAP、用友、业务数据库 | 不涉及 |
| L3 | 制造执行层 MES / WMS | IT | 工单、质量追溯、排产、API 对接 | **可迁移** |
| — | — | **IT / OT 分界** | — | — |
| L2 | 监控层 SCADA / HMI | OT | 组态画面、实时告警、历史曲线 | 要补 |
| L1 | 控制层 PLC / DCS | OT | 梯形图、毫秒级循环扫描 | **核心缺口** |
| L0 | 现场设备层 | OT | 传感器、电机、阀门、机床 | 了解即可 |

## 三、IT 与 OT 的本质差异（面试高频）

| 维度 | IT（信息技术） | OT（运营技术） |
|------|---------------|---------------|
| 处理对象 | 数据 | 物理设备 |
| 时间尺度 | 秒级可接受 | 毫秒级硬实时 |
| 宕机后果 | 页面打不开 | 设备撞机、人员伤亡、批次报废 |
| 升级方式 | 随时重启 | 只能等停机窗口（常为节假日/夜间） |
| 系统寿命 | 3-5 年 | 10-20 年（大量仍在跑 WinXP / Win7） |
| 优先序 | CIA：机密性 > 完整性 > 可用性 | **AIC：可用性 > 完整性 > 机密性** |

**最后一行是面试杀手锏。** 互联网人默认"安全最重要"，工厂里"先别停产"排第一。能说出这个倒序，说明你懂 OT。

## 四、协议速查卡（补缺口最便宜的一步）

三个协议不在同一层，**不要混着说**。

| 协议 | 在哪一层 | 解决什么问题 | 传输 | 数据模型 |
|------|---------|-------------|------|---------|
| **Modbus RTU** | L1 ↔ L0 | 让 PLC 读一个寄存器的值 | RS-485 串口 | 裸寄存器地址（40001 这种） |
| **Modbus TCP** | L2 ↔ L1 | 同上，但走以太网 | TCP 502 | 同上，加 MBAP 头 |
| **OPC UA** | L2 ↔ L3 / 云 | 跨厂商语义互通 | TCP 4840 | 带类型的地址空间（对象+属性） |
| **MQTT** | 边缘 ↔ 云 | 海量设备低带宽上报 | TCP 1883/8883 | 主题 + 载荷（payload 无结构） |

**一句话记法：**

> **Modbus 解决"读得到"，OPC UA 解决"读得懂"，MQTT 解决"传得远"。**

**面试能说的边界：**

- "Modbus 是寄存器级的，拿到的是 40001 这个地址里的一个数，不知道它代表温度还是压力——得对着点表查。"
- "OPC UA 自带地址空间和类型信息，跨厂商不用再对着点表翻译，这是它替代 Modbus 上层位置的原因。"
- "MQTT 只管把 payload 送到，不管里面是什么，所以上云之后还得再做一层建模。"

能说出这三句，就不算"完全不懂 OT"。**半天能补完。**

## 五、本人在链路中的位置

```
传感器 → PLC → 边缘网关 → 平台/云 → 应用
  ?       ?      ✓已具备    ✓已具备    ~
 毫秒    毫秒     秒级      分钟     非实时
```

**AWS IoT 管道项目（ESP32 → MQTT → Ubuntu 网关 → AWS Cloud）覆盖的正是第 3、4 环。**

缺口在第 1、2 环：数据怎么从传感器进 PLC、PLC 怎么把数据交给网关。

**面试话术（把缺口转成加分项）：**

> 我做的是设备数据上云这一段——边缘侧用 Linux 网关做采集和协议转换，通过 MQTT 送到云端时序库。现场总线这一段我不熟，但我的定位就是 IT 侧：把 OT 侧已经采集到的数据接出来、传上去、用起来。PLC 那边由电气工程师负责，我负责对接。

**这句话的作用**：承认边界，同时把自己放到"IT 侧负责人"的位置上——这恰恰是很多制造业数字化岗招人的真实需求（工厂里有电气工程师，缺的是懂 IT 的人）。

## 六、为什么这个认知对求职有用

1. **岗位名称对上了。** "数字化运维工程师""智能制造系统运维员""工业互联网实施"——这些岗位的本质就是在这条链的第 3-4 环干活。
2. **技能稀缺性翻转。** Linux/Docker/MQTT/Python 在互联网过剩，在工厂里稀缺。工厂不缺会写业务代码的人，缺能让设备数据连上云的人。
3. **不在校招体系里。** 制造业甲方的数字化岗走社招/内推/本地招聘，没有测评、没有群面。

## 七、证据强度

- **强**：ISA-95 分层为标准工业规范；IT/OT 的 CIA vs AIC 优先序为业界定论；四个协议的技术特征为公开标准。
- **中等**："工厂计算机数量多于互联网公司"为合理推断，无直接统计。
- **待本人核验**：具体企业的分层落地形态差异很大，小厂可能 L2/L3 合一甚至直接从 PLC 上云。
