# 公司背调方法论

> 背调不是"查清楚公司好不好",而是"识别明显风险"。skill 不替用户做决定,只提供客观信息。

## 数据源优先级(skill 按此顺序查询)

### 第一优先:工商核验(必须做)

1. **企查查/天眼查 MCP**(如已连接)
   - 统一社会信用代码
   - 注册资本 vs 实缴资本
   - 成立日期
   - 社保缴纳人数
   - 经营异常
   - 司法风险(失信/被执行)

2. **若 MCP 未连接**,提示用户手动访问:
   - 企查查:https://www.qcc.com/
   - 天眼查:https://www.tianyancha.com/
   - 国家企业信用信息公示系统:http://www.gsxt.gov.cn/

### 第二优先:司法核查(查欠薪)

- **中国裁判文书网**:https://wenshu.court.gov.cn/
- 搜索:"{公司名} 劳动合同""{公司名} 拖欠工资"
- 命中 = P0 红旗

### 第三优先:社区口碑(查文化)

| 平台 | 搜什么 | 信任度 |
|------|--------|--------|
| 脉脉 | "{公司} 工作体验" | 高(实名职场) |
| 看准网 | "{公司} 评价" | 中(匿名) |
| 知乎 | "{公司} 怎么样" | 中 |
| V2EX / linux.do | "{公司}" | 高(技术圈真实) |
| 小红书 | "{公司} 避雷" | 中(偏情绪) |

### 第四优先:官网验证

- WebFetch 公司官网 About 页
- 确认业务是否真实
- 评估专业度(官网粗糙 = 警惕)

## 背调流程(skill 执行顺序)

```
1. 核验身份(工商)
   → 确认是合法注册公司
   → 若查不到 = 立即停止,可能是皮包

2. 扫描风险(红旗库)
   → 对照 red-flags-database.md 逐项
   → 命中 P0 直接亮红灯

3. 查口碑(社区)
   → 搜索加班/欠薪/裁员关键词
   → 提取客观信息,过滤情绪

4. 综合评分
   → 红/黄/绿三色
   → 输出建议(但不替用户决定)
```

## 追问话术(面试时反向验证)

背调查到的疑点,面试时巧妙追问:

| 疑点 | 追问话术 |
|------|---------|
| 社保人数少 | "咱们团队现在多少人?技术团队占比?" |
| 成立不久 | "公司目前融资到什么阶段?盈利模式是?" |
| 加班文化 | "团队一般几点下班?周末需要到吗?" |
| 流动率高 | "这个岗位是新开的还是有人离职?" |
| 外包嫌疑 | "咱们是做自研产品还是项目交付?" |

## 局限性声明(skill 必须告知用户)

- 工商数据有滞后(社保人数可能滞后 3-6 个月)
- 社区评价主观(离职员工倾向负面)
- 小公司信息少 ≠ 不靠谱
- **skill 不输出"一定不能去"的结论,只说"建议警惕"**

## skill 调用提示

- skill 启动读 `config/profile.yml` 了解用户目标城市/行业
- 检测到公司名后,按上述流程执行
- 参考 `red-flags-database.md` 做风险判断
