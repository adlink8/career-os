# STAR 法则简历应用指南

> STAR = Situation(情境) · Task(任务) · Action(行动) · Result(结果)
> 简历项目经历**必须用 STAR 重写**,避免"做了 XX"的流水账。

## STAR 四要素

| 要素 | 含义 | 简历中的体现 | 必须? |
|------|------|------------|------|
| **S** 情境 | 项目背景/面临的问题 | 项目简介一句 | 可选(简历精简时可省) |
| **T** 任务 | 你的职责 | "负责 XX" | 必须 |
| **A** 行动 | 你具体做了什么 | 动词开头的技术细节 | 必须 |
| **R** 结果 | 量化成果 | 数字/百分比/对比 | **必须**(无结果 = 无效) |

## 反面 vs 正面对照

### ❌ 流水账(无效)

```
负责 AWS IoT 项目,搭建了数据管道,排查了设备掉线问题。
```

### ✅ STAR 重写(有效)

```
(S)AWS IoT 数据采集项目,设备频繁掉线影响数据完整性
(T)负责排查设备掉线根因并优化管道稳定性
(A)通过分析 MQTT 日志,定位到 keepalive 参数配置问题;
    调整 keepalive 间隔并优化重连逻辑
(R)设备在线率从 85% 提升至 99%,数据丢失率降至 0
```

## 动词库(简历用)

避免"参与了""帮忙做了",用强动词:

| 类别 | 推荐动词 |
|------|---------|
| 建设 | 搭建、部署、设计、实现、开发 |
| 优化 | 优化、提升、改进、重构、调优 |
| 排查 | 定位、排查、解决、修复、根因分析 |
| 主导 | 负责、主导、牵头、推进 |
| 量化 | 提升 X%、降低 Y%、达到 Z |

## 结果量化模板

没有数字的项目**不写**。常见量化角度:

| 维度 | 量化方式 | 示例 |
|------|---------|------|
| 性能 | 延迟/吞吐/QPS | "QPS 从 100 提升至 1000" |
| 稳定性 | 可用性/在线率 | "在线率 85% → 99%" |
| 规模 | 数据量/用户量 | "支撑日均 100 万条数据" |
| 效率 | 时间节省 | "部署时间从 2h 降至 10min" |
| 成本 | 资源节省 | "服务器成本降低 30%" |

## skill 调用提示

- 简历定制时,对 profile.yml 的每个 project 应用 STAR 重写
- 强制要求每个项目至少 1 个量化结果
- 无法量化的项目 → 追问用户补齐,或弱化处理
