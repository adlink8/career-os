# ATS 简历优化策略

> ATS = Applicant Tracking System(申请人追踪系统),大中厂普遍用 ATS 自动筛简历。
> 简历过不了 ATS = HR 看不到,无论多优秀。

## ATS 工作原理(简化)

```
你的简历 PDF/Word
      ↓
ATS 解析文本
      ↓
关键词匹配(JD 中的技能词)
      ↓
评分排序 → 前 X% 才被 HR 看到
```

## ATS 友好性检查清单

### 格式(格式错 = 解析失败)

- [ ] **用 PDF 或 .docx**,不要用图片/PPT/网页
- [ ] **单栏布局**,双栏 ATS 经常解析错乱
- [ ] **标准字体**(宋体/微软雅黑/Times),不要花体
- [ ] **不用表格/文本框**,ATS 解析不出
- [ ] **不用页眉页脚**放关键信息(可能被忽略)
- [ ] **文件名规范**:`姓名_岗位_简历.pdf`

### 关键词(命不中 = 低分)

- [ ] JD 硬性关键词**全部出现**(见 `jd-templates/ops-keywords.md`)
- [ ] 用**精确词**,不用同义词("Docker" 不要写"容器技术")
- [ ] 技能词放在显眼位置(技能栏 + 项目里都出现)
- [ ] **不要堆砌**(全文塞满关键词会被反作弊识别)

### 内容(语义可读)

- [ ] 联系方式用标准格式(手机号、邮箱独立行)
- [ ] 日期格式统一(2024.06 或 2024-06,不要混用)
- [ ] 公司名/学校名写全称
- [ ] 避免 URL 缩短/二维码(ATS 不识别)

## 关键词命中策略

### 投递前:JD 关键词抽取

```
1. 从 JD 提取所有技能词(参考 jd-templates/)
2. 分类:硬性(必须命中)/ 加分(尽量命中)
3. 对照简历,确保硬性词全部出现
4. 缺失的关键词 → 在技能栏补 + 项目里自然融入
```

### 多版本简历策略

针对不同岗位,维护多份简历:

| 版本 | 强调 | 弱化 |
|------|------|------|
| 运维版 | Linux/排障/监控 | AI 项目 |
| IoT 版 | MQTT/AWS IoT/设备接入 | 大数据 |
| AI 运维版 | RAG/LangChain/Agent | 网络组网 |
| 通用版 | 平衡,适合海投 | - |

派生文件落到 `data/cv/cv-{role}.md`(已 gitignore)。

## ATS 不友好的写法(避免)

| ❌ 避免 | ✅ 改为 |
|---------|--------|
| "熟悉容器技术" | "Docker / Kubernetes" |
| "会脚本语言" | "Python / Shell / Bash" |
| "做过云相关" | "AWS IoT / 阿里云 ECS" |
| "有数据库经验" | "MySQL / Redis" |
| "负责过项目" | "主导 X 项目,Y 人协作" |

## skill 调用提示

- 简历定制 skill 必须做 ATS 检查
- 输出时标注:JD 关键词命中率 X/Y
- 低于 70% 命中 → 警告用户投递前优化
