# Owner 化写作:角色强度分级与来源映射

> 改编自 Claycui828/ASu-resume-skills `skills/asu-resume-skill/SKILL.md` 的生成原则。
> 用途:`career-general-recruit` 生成/改写简历时,在不造假的前提下把表达力拉满。

## 核心原则:只增强表达,不创造事实

允许:
- 把真实技术过程整理成链路(`采集 → 清洗 → 索引 → 检索 → 评估`)
- 集中呈现同一项目里真实使用的框架/组件/术语
- 用 `RAG / MCP / Eval / Workflow / Benchmark` 等与项目相符的术语

禁止:
- 新增不存在的角色、指标、结果
- `参与` 改 `主导`;`规划中` 改 `已上线`
- 改写原始分母;团队成果暗示个人完成

## 角色强度按证据分级(选词规则)

| 证据强度 | 可用表述 | 示例(本项目素材) |
|----------|----------|-------------------|
| 独立完成最小闭环 | `模块级 Owner` / `端到端 Owner` / `从 0→1`(限定到该闭环) | "数据索引链路 Owner:从 0→1 打通 采集→清洗→知识单元→检索服务" |
| 主要负责有边界 | `方向负责人` / `策略架构 Owner`(正文写清边界) | "RAG 评估体系负责人(切块与检索策略部分)" |
| 参与共建 | `核心参与者` / `共建者` | 不伪造全局 Owner |
| 规划中/学习中 | `当前方向` / `建设中` | K8s 一律写"学习中" |

**Owner 化拆分法**:每个项目先找"本人真正独立完成的最小闭环",对该闭环可以用 Owner/0→1,但作用域不得外扩。

## 来源映射(每条 bullet 可追溯)

写简历时,每条 bullet 内部标记来源强度(不印在简历上,留在素材库备查):

- `source_grounded` — cv-material.md / 仓库证据里有据可查
- `user_attested` — 用户口述,无公开核验载体(面试要备好讲法)

cv-material.md 的条目已按此维护;新增 bullet 时同步补证据来源。

## 学校 Title 增强(如实版)

教育经历可查官方标签如实使用,不夸大:

- 本科阶段: 可查"省高水平大学建设/特色专业"等官方序列(使用前核实原文与 URL)
- 专科/高职阶段: 重点突出技能竞赛与核心项目，如实即可，不贴不存在的标签

规则:学位、学籍、合作/联合项目分开写;不把地理位置或合作项目写成学位主体。

## 项目 bullet 固定结构(高密度版)

```
### 项目名(角色限定)
`技术栈标签行`
- [背景一句:什么场景什么问题]
- [指标与效果:量化成果前置,口径可解释]
- [我的职责:技术链/排障/闭环,动词开头]
- [技术关键词融在句子里,不裸列]
```
