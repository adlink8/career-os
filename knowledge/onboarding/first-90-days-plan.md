# 前 90 天行动计划

> 来源:[daily.dev 90 天 Playbook](https://recruiter.daily.dev/resources/developer-onboarding-first-90-days-playbook-engineering-teams/) + 社区经验。
> 前 90 天决定未来 2-3 年的发展轨迹。

## 三个阶段

```
第 1 个月(1-30 天):学习与融入
  目标:搞清楚环境,能独立完成小任务
  
第 2 个月(31-60 天):承担与贡献
  目标:独立负责模块,主动发现问题
  
第 3 个月(61-90 天):证明与转正
  目标:有量化成果,顺利转正
```

## 第 1 个月(1-30 天)

### 学习目标

- [ ] 完全熟悉公司业务和产品
- [ ] 掌握团队技术栈(80%)
- [ ] 熟悉代码库/系统架构
- [ ] 理解团队工作流程(发布/排障/复盘)

### 工作目标

- [ ] 独立完成 3-5 个小任务
- [ ] 参与至少 1 次发布
- [ ] 跟班 1 次完整的故障处理
- [ ] 写 1 篇入职笔记(沉淀所学)

### 人际目标

- [ ] 认识跨团队协作的关键人
- [ ] 找到一个"职场伙伴"(同期/同组)
- [ ] 与 mentor 建立 1v1 沟通节奏

### 检查点(Day 30)

- 能独立完成常规任务
- 知道遇到不同问题找谁
- 融入团队(被叫去吃饭/参与闲聊)

## 第 2 个月(31-60 天)

### 工作目标

- [ ] 独立负责一个模块/小项目
- [ ] 主动发现并修复 1-2 个问题
- [ ] 优化一个现有流程(文档/脚本/监控)
- [ ] 参与一次代码评审 / 方案评审

### 技能提升

- [ ] 深入掌握团队核心技术
- [ ] 开始学习一个进阶方向(对应用户的 K8s/CI-CD)
- [ ] 总结团队最佳实践,做内部分享(加分)

### 检查点(Day 60)

- 能独立 owner 一个任务
- 主动提出过改进建议
- 开始有"自己的判断",不全靠问

## 第 3 个月(61-90 天)

### 工作目标

- [ ] 完成 1 个有量化成果的项目(转正筹码)
- [ ] 处理过至少 1 次线上问题(运维岗)
- [ ] 参与 1 次复盘并输出文档
- [ ] 建立自己的工作节奏

### 转正准备

- [ ] 整理 90 天工作成果(量化)
- [ ] 准备转正述职/汇报
- [ ] 收集同事/领导反馈
- [ ] 明确后续 3-6 个月的发展方向

### 检查点(Day 90)

- 有可量化的成果(性能提升 X% / 处理故障 Y 次 / 自动化 Z 项)
- 获得转正
- 清楚下一阶段目标

## 用户专属(运维岗)

### 第 1 个月重点

- 熟悉所有服务器/服务清单
- 看懂监控大屏,知道每个指标含义
- 熟悉发布流程,能跟着发布

### 第 2 个月重点

- 独立处理常见告警
- 写 1-2 个自动化脚本(用户 Python 强项)
- 开始接 oncall(在 mentor 陪同下)

### 第 3 个月重点

- 独立 oncall 一个班次
- 主导一个小优化(监控补全/脚本自动化/文档完善)
- 用 STAR 整理转正成果

## 90 天红线

### ❌ 绝对不要

- 试用期被开除(态度问题 > 能力问题)
- 严重线上事故(未经授权操作生产)
- 与同事/领导严重冲突
- 频繁迟到/旷工

### ⚠️ 警惕信号(需立即调整)

- Day 30 还不能独立做任何事
- 同样的错误犯第二次
- 同事/领导反馈"态度有问题"
- 完全不融入团队

## skill 调用提示

- 用户入职后,skill 按 30/60/90 天节点主动提醒检查
- 每个节点让用户对照本计划自检
- 转正前帮用户用 STAR 整理成果
