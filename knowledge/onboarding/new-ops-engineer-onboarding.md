# 运维新人专属入职指南

> 运维岗的特殊性:接触生产环境,容错率低,权限大。
> 运维新人最容易"好心办坏事",本指南帮用户安全度过新手期。

## 运维新人三大铁律

### 1. 生产环境,先问后做

- **任何生产操作** 必须先确认 + 有人 review
- 不要"我觉得这样可以"就执行
- 高危操作(rm/mv/restart)必须有回滚方案

### 2. 权限越大,责任越大

- 拿到 root/sudo 不等于可以随便用
- 所有 sudo 操作记录在案
- 不在服务器上做与工作无关的事

### 3. 不懂就问,不要瞎猜

- 运维操作影响线上,**瞎猜 = 制造事故**
- 不确定就问 mentor 或老员工
- 宁可被嫌烦,不要捅篓子

## 第一周运维专属清单

### 环境熟悉

- [ ] 拿到堡垒机/跳板机账号
- [ ] 熟悉服务器清单(多少台/什么配置/跑什么)
- [ ] 了解网络拓扑(运维必须画得出来)
- [ ] 找到并读懂监控大屏

### 流程熟悉

- [ ] 发布流程(谁发起/谁 review/谁执行)
- [ ] 故障响应流程(告警 → 响应 → 升级 → 复盘)
- [ ] 变更管理流程(工单/审批)
- [ ] 值班/oncall 排班

### 工具熟悉

- [ ] 监控系统(Prometheus/Zabbix/Zabbix)
- [ ] 日志系统(ELK/EFK)
- [ ] 工单系统(Jira/Tower)
- [ ] 沟通工具(钉钉/企微)
- [ ] 配置管理(Ansible/SaltStack)

## 运维新人的"安全操作清单"

### ✅ 可以独立做的(低风险)

- 看监控、看日志(只读)
- 写文档、整理清单
- 在测试环境练习
- 跟着老员工观察
- 写自动化脚本(本地/测试环境)

### ⚠️ 需要 mentor 确认的(中风险)

- 重启非核心服务
- 修改配置文件
- 执行运维脚本
- 处理普通告警

### 🚫 绝对不能独立做的(高风险)

- rm/mv 生产数据
- 修改数据库(无 review)
- 关闭防火墙/监控
- 给服务器开公网
- 任何"删"类操作

## 运维新人的常见坑

### 坑 1:scp/rsync 拷错方向

```
❌ scp remote:/data local   (这是从远端拷到本地)
✅ 确认方向再执行
```
**教训:** 拷贝前先用 dry-run 或 ls 确认。

### 坑 2:crontab 写错

```
❌ * * * * * rm /tmp/*    (每分钟执行一次 rm!)
✅ 先在测试环境验证
```

### 坑 3:重启服务影响用户

```
❌ 白天高峰期 restart 核心服务
✅ 在变更窗口(凌晨/低峰)操作
```

### 坑 4:配置改了没备份

```
❌ 直接 vim 改生产配置
✅ cp config config.bak.20260614 再改
```

### 坑 5:sudo 滥用

```
❌ 什么都 sudo
✅ 最小权限原则,需要时才 sudo
```

## 运维新人的成长路径(3 个月)

### Month 1:观察者

- 看懂监控系统
- 看懂告警含义
- 跟着 oncall,不主导

### Month 2:辅助者

- 处理低优先级告警
- 写自动化脚本(被审核后执行)
- 参与发布(跟着执行)

### Month 3:独立者

- 独立 oncall 一个班次(有 backup)
- 主导小优化(监控/脚本/文档)
- 能独立处理常见故障

## 用户优势发挥

基于 profile.yml,用户的**Python 强项**在运维岗是稀缺优势:
- 主动提议写自动化脚本(监控/巡检/报表)
- 用 Python 做 Ansible 替代/补充
- 这是用户快速建立价值的突破口

## skill 调用提示

- 用户入职后,skill 提醒"运维三大铁律"
- 按周/月节点提醒检查清单
- 用户遇到具体操作犹豫时,提醒"先问后做"
