# 转正述职与谈判指南

> 转正是试用期的最终考核,也是第一次谈涨薪/定级的机会。
> 提前 1 个月准备,用数据和成果说话。

## 转正流程(国内常见)

```
试用期结束前 1 个月
      ↓
HR/领导发起转正评估
      ↓
员工提交转正申请(述职报告 + 成果)
      ↓
领导评估 + 360 反馈
      ↓
转正审批(部门 + HR)
      ↓
转正谈话(确认薪资/职级/后续发展)
      ↓
正式转正 / 延长试用期 / 不通过
```

## 转正述职报告模板

### 结构(5 部分)

```
1. 试用期概述(200 字)
   - 入职时间/岗位/主要职责

2. 工作成果(核心,占 60%)
   - 量化成果(数字!)
   - STAR 案例化呈现
   - 对照 JD 要求逐条回应

3. 能力提升(占 20%)
   - 学到的技术/工具/流程
   - 参加的培训/分享

4. 不足与改进(占 10%)
   - 真实但可控的不足
   - 具体改进措施

5. 后续规划(占 10%)
   - 未来 3-6 个月目标
   - 期望的发展方向
```

### 成果量化(关键)

**❌ 流水账:**
```
我做了服务器巡检,处理了一些告警,写了一些脚本。
```

**✅ 量化:**
```
- 独立处理告警 47 次,平均响应时间 8 分钟(团队平均 15 分钟)
- 编写 Python 自动化脚本 5 个,减少重复巡检工作量约 60%
- 完善监控指标 12 项,提前发现潜在故障 3 次
- 输出运维文档 8 篇,被团队采纳为新人培训材料
```

### STAR 案例化(选 1-2 个亮点)

```
亮点案例:核心服务故障应急处理

S:某日凌晨,核心服务 CPU 飙升至 95%,影响用户
T:作为值班人员,需快速定位并恢复
A:通过 top 定位异常进程 → 分析日志发现死循环 →
   重启服务临时恢复 → 联合开发定位根因 → 推动修复
R:30 分钟内恢复服务,事后主导复盘并产出预防方案
```

## 转正谈话策略

### 准备工作

- [ ] 整理 90 天成果(量化)
- [ ] 收集同事/领导正向反馈(聊天截图/邮件)
- [ ] 了解同岗位市场薪资(谈薪筹码)
- [ ] 准备 3-5 个发展目标(展现上进心)

### 谈话中的应对

**领导问:"这三个月感觉怎么样?"**
- ✅ "学到了 X / Y / Z,感谢团队帮助,我也发现了自己在 A 方面需要加强"
- ❌ "还行吧"(显得不上心)

**领导问:"后续有什么想法?"**
- ✅ "我想在 X 方向深入,目标是在 6 个月内能独立 owner Y 类项目"
- ❌ "没想好"(显得没规划)

**HR 谈薪资:**
- 参考 `salary-data/negotiation-scripts.md`
- 转正是天然谈薪节点,不要错过
- 用成果 + 市场行情 + 同岗位对比说话

## 转正谈判筹码

### 强筹码

- 有量化成果(数据)
- 领导/同事正面反馈
- 同岗位市场薪资高于当前
- 有竞品 offer(谨慎使用)

### 弱筹码(慎用)

- "我加班很多"(应该的)
- "别人都涨了"(攀比)
- "不涨我就走"(威胁,除非真有备选)

## 如果转正不顺

### 情况 1:延长试用期

- 冷静分析原因(能力?融入?)
- 与领导明确延长期间的改进目标
- 制定具体改进计划
- 延长期内全力改进

### 情况 2:不通过(被辞)

- **不要情绪化**(虽然很难)
- 争取合理补偿(试用期辞退也有 N 或协商)
- 要求 HR 出具书面理由(防扯皮)
- 复盘原因(避免下次踩同样坑)
- 立即启动求职(不要空窗太久)

### 情况 3:转正但薪资没涨

- 接受现实(先转正要紧)
- 明确下次调薪节点(半年/一年)
- 在转正谈话中争取"明确调薪承诺"
- 用这一年积累经验,第二年跳槽涨薪

## 用户专属建议

基于 profile.yml:
- **优势:** 有 AWS IoT + 竞赛经验,转正成果容易量化
- **方向:** 运维岗的自动化能力是稀缺(用户 Python 强)
- **薪资:** 转正时争取从 4-6k 涨到 6-7k(用成果说话)
