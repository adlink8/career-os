# LC20 有效的括号（简单）

> 一句话考点：左括号压栈记账，右括号弹栈对账 | 模式：栈（后进先出）

## 题面

给定一个只包括 `'('`、`')'`、`'{'`、`'}'`、`'['`、`']'` 的字符串 `s`，判断字符串是否有效。

有效字符串需满足：左括号必须用**相同类型**的右括号闭合；左括号必须以**正确的顺序**闭合；每个右括号都有一个对应的相同类型的左括号。

```text
示例 1：s = "()"     → true
示例 2：s = "()[]{}" → true
示例 3：s = "(]"     → false（类型不配）
示例 4：s = "([)]"   → false（顺序错：[ 还没被 ( 放走就被要求闭合）
示例 5：s = "{[]}"   → true（正确嵌套）
```

约束：`1 <= s.length <= 10^4`，`s` 仅由括号 `'()[]{}'` 组成。

<details><summary>💡 提示第 1 档·方向（点开前先自己想 3 分钟）</summary>

想象你从左到右读这串符号，每遇到一个**左**括号就先"记账"——因为闭合它的右括号一定在**将来**才出现。而"最新的债最先被还"：`"([])"` 里最后记账的 `[`，必然是最先等到 `]` 来配对的。什么东西天生就是"最后放的先取出"？
</details>

<details><summary>💡 提示第 2 档·模式点名</summary>

栈——一个只能从同一端存取的桶（Python 里直接用 list 的 append 和 pop 就是栈）。左括号入栈，右括号来时弹栈顶去配对。配对关系可以用一个字典查表：右括号 → 它要找的左括号。
</details>

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. 造一个空栈和一个配对表：右括号做钥匙，对应的左括号做值；
2. 从左到右逐个字符看；
3. 是左括号（不在配对表的钥匙里）：压进栈，继续；
4. 是右括号：先检查栈空不空——空了说明右括号多了，直接交 false；
5. 栈不空就弹出栈顶，和配对表查出的"该配的左括号"比，不一样交 false；
6. 字符全看完后，检查栈——**还剩东西说明左括号多了**，交 false；
7. 栈也空了才交 true。两个"多的"检查一个都不能少。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：字符串 s，从左到右一个字符一个字符看。
2. 记录什么：一个栈（列表），装还没等到配对的左括号。
3. 怎么判断/返回：左括号入栈；右括号弹栈配对，配不上或栈空都返回 False；走完全部字符后栈非空也返回 False，栈空才返回 True。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

```python
class Solution:
    def isValid(self, s: str) -> bool:
        pairs = {')': '(', ']': '[', '}': '{'}
        stack = []
        for ch in s:
            if ch in pairs:
                if not stack or stack[-1] != pairs[ch]:
                    return False
                stack.pop()
            else:
                stack.append(ch)
        return not stack
```

- 第 3 行 `pairs = {')': '(', ']': '[', '}': '{'}` —— 配对查表：钥匙是右括号，值是它想找的左括号。用字典的好处：判断"是不是右括号"只需 `ch in pairs`，配对只需查一次表，不用写三个 if 分支。注意花括号里写成 `'(' : ')'` 键值倒过来也行，但整套判断要跟着翻——认准"右做钥匙"这个版本，判断逻辑最顺。
- 第 4 行 `stack = []` —— 造一个空桶。Python 的 list 天生是栈：`append` 从尾放进，`pop` 从尾取出，`stack[-1]` 看尾端但不取。没有单独的 Stack 类要背，list 即栈。
- 第 5 行 `for ch in s:` —— 从左到右逐字符看。
- 第 6 行 `if ch in pairs:` —— 是右括号吗？在配对表的钥匙堆里就是。
- 第 7 行 `if not stack or stack[-1] != pairs[ch]: return False` —— 弹栈前的两道安检合并一行：①栈空了还来右括号——右括号多了（如 `")("` 走到第一个字符）；②栈顶左括号和该配的对不上——类型错或顺序错（如 `"(]"`、`"([)]"`）。`not stack` 必须写在 `or` **左边**：栈空时 `stack[-1]` 会越界报错，短路求值先挡住它——顺序即保命，和 LC14 的长度检查同一课。反过来会怎样：只查 `stack[-1]` 不查空，`)` 打头的串当场 `IndexError`；只查空不比对，`(]` 混过安检返回 true。
- 第 9 行 `stack.pop()` —— 安检通过，债还清了，把栈顶左括号从桶里取出扔掉。
- 第 11 行 `stack.append(ch)` —— 左括号入桶记账，等将来的右括号来还。
- 第 12 行 `return not stack` —— 在 for **外面**。字符串走完，桶里空不空说了算：空 = 每笔账都还清 = true；不空 = 还有左括号没人配 = 左括号多了（如 `"(("`）。写 `return True` 是新手最高频错误——`"("` 会被误判成有效。`not stack` 是"栈为空"的地道写法，等价于 `len(stack) == 0`。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **结尾写 `return True`**：现象——`"("`、`"()("` 返回 true。病因：只顾右括号多了的情况，忘了左括号可能没还清。修复：结尾 `return not stack`，用栈的余额下结论。
2. **弹栈前不查空**：现象——`")"` 或 `"())"` 报 `IndexError`。病因：栈空时没有栈顶可弹。修复：`if not stack or ...` 且把空检查放左边吃短路。
3. **字典键值反着造又照抄判断**：现象——所有输入都判错。病因：`pairs = {'(': ')'}` 时 `ch in pairs` 查的是"是不是左括号"，后面弹栈比对全乱了。修复：跟着选定的版本走，键值方向和判断逻辑要配套。
4. **`pop()` 写成 `pop(0)`**：现象——简单嵌套对、`"([)]"` 也判 true。病因：`pop(0)` 从队头取，那是队列不是栈——后进先出变先进先出，配对顺序全错。修复：栈只从尾部进出，`pop()` 不带参数。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"为什么是栈不是别的"——尤其 `"([)]"` 这种顺序错例，用列表手推一次：`(` 入、`[` 入、`]` 来时栈顶是 `[` 配对了、`)` 来时栈顶却是空了（[ 被弹走了）才发现假。推一遍就懂"最新未闭合的必须最先闭合"。
2. 最容易漏的动作：结尾的 `return not stack`（左括号多了的检查），以及弹栈前的空栈安检。
3. 为什么快：暴力是"每次找一对相邻的 `()`/`[]`/`{}` 删掉，找不到就检查剩没剩"——每删一对都要重扫一遍串，最坏 O(n²)；栈解法每个字符进出桶各一次，O(n) 时间 O(n) 空间。它快的本质：栈把"最近欠的债"永远放在手边，配对不用回头找。
4. 信号词："配对""嵌套""合法闭合""正确顺序"→ 栈。嵌套结构和栈是天生一对：最内层最先完成，对应栈顶最先弹出。
5. 变式：求最长有效括号子串的长度？（LC32，仍是栈，栈里存下标；hard 但骨架同源。）消消乐——相邻相同字符成对消除（LC1047，栈：字符等于栈顶就弹，否则压）。
</details>
