双指针——left 从 0 出发、right 从末尾出发，相向而行，每轮做一次交换。Python 里交换两个变量有现成写法（逗号两边一换）。循环只走到两人相遇为止。

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. left 站 0 号位，right 站最后一格；
2. 循环条件：left 还没越过 right；
3. 每轮把 left 位置的字符和 right 位置的字符**互换**；
4. left 往右挪一格，right 往左挪一格；
5. 两人相遇或交叉时停止——因为换到中点，两边已经对称换完了，再换就是把换好的换回去；
6. 这题没有 return，函数结束时 s 已经被改好了。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：不遍历新东西，是 left 和 right 两个下标从两头往中间走。
2. 记录什么：什么都不记，原地改 s。
3. 怎么判断/返回：每轮交换 s[left] 和 s[right]，两指针靠拢；left >= right 时循环结束，s 就地反转完成。没有返回值。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

**解法 A·双指针原地交换版（面试要的）**

```python
class Solution:
    def reverseString(self, s: list[str]) -> None:
        left, right = 0, len(s) - 1
        while left < right:
            s[left], s[right] = s[right], s[left]
            left += 1
            right -= 1
```

- 第 3 行 `left, right = 0, len(s) - 1` —— 两个搬运工就位。右边界 `len(s) - 1`：下标从 0 数起，最后一格是长度减一。
- 第 4 行 `while left < right:` —— 没碰面就继续。**范围必须是走一半**：相遇即停，交叉更不该发生。写成 `left <= right` 的话，奇数长度时中间那个字符会和自己换一次（无害但是废动作）；更重要的是体会"为什么一半就够"——每一轮交换修好**两个**位置，n/2 轮正好修完全部。
- 第 5 行 `s[left], s[right] = s[right], s[left]` —— Python 的同步交换：右边先把两个原值打包成一组，再按顺序发给左边，**不存在覆盖丢失**。反过来会怎样：如果按老三样写 `tmp = s[left]` 再 `s[left] = s[right]` 再 `s[right] = tmp` 也对，但直接写 `s[left] = s[right]` 而没有暂存，left 位置原来的字符就被覆盖丢了，最后整串会变成左右两半互抄。别忘了 `=` 左右两边的 `s` 一个都不能省——写成 `left, right = right, left` 只是把两个下标对调，数组纹丝不动。
- 第 6 行 `left += 1` —— 左边这个人往中间挪一步。
- 第 7 行 `right -= 1` —— 右边这个人也往中间挪一步。这两行漏掉任何一行，下标不动，while 永远成立，**死循环**卡死程序。

**解法 B·一行版（知道有，面试别交这个）**

```python
class Solution:
    def reverseString(self, s: list[str]) -> None:
        s[:] = s[::-1]
```

- `s[::-1]` 是"整串倒过来拷贝一份"，`s[:] =` 是把拷贝**灌回**原列表（原地修改内容）。注意必须写 `s[:] =` 不能写 `s =`：`s =` 只是把变量名指向新列表，函数外面的原列表根本没变——题目要的是"改原数组"。一行版简洁但考察点（双指针+交换）全丢，练完 A 再看它。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **交换漏暂存导致覆盖**：现象——结果左右两半互抄，如 `["h","e","l","o"]` 变 `["o","e","l","o"]`。病因：`s[left] = s[right]` 先把左边覆盖了，右边再取左边时取到的已经是新值。修复：用 Python 同步交换 `s[left], s[right] = s[right], s[left]`，或老三样带临时变量。
2. **`return s` 或函数返回了东西**：现象——本地能跑但 LeetCode 判错。病因：签名要求原地改、不返回；写成 return 虽然很多判题器不报，但违背考察点。修复：什么都不 return，靠修改 s 本身。
3. **循环范围写成 `left <= len(s) // 2` 类的错误边界**：现象——没换全或多换。病因：自己发明边界容易错。修复：认准 `while left < right`，两人相遇即停，中点位置奇偶通吃，不需要单独处理。
4. **忘挪指针死循环**：现象——程序卡死不动。病因：交换写了但 `left += 1` 或 `right -= 1` 漏了一行，条件永远为真。修复：交换和挪步是固定三连，一起写。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"原地"俩字——第一反应都是造个新列表倒着塞回去，卡点在想不到交换这个动作本身就是反转。
2. 最容易漏的动作：每轮**挪指针**（漏一行就死循环）。
3. 为什么快：暴力也可以新开 O(n) 数组倒着拷贝，或用 `s[::-1]`——都多花一倍内存；双指针原地交换时间 O(n/2)=O(n)、空间 O(1)，每个字符只被摸一次。
4. 信号词："原地""不分配额外空间""O(1) 空间"→ 原地双指针交换。反转、对调类操作 → 首尾夹。
5. 变式：反转整数 7 → 反转字符串里的单词顺序（LC151，先整体反转再逐词反转，同一招套两层）；只反转字母、数字和符号留在原位（LC917，left/right 跳过非字母再交换——和 LC125 的跳法合体）。
</details>
