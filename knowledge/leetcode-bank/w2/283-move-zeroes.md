# LC283 移动零（简单）

> 一句话考点：快指针开路，慢指针管"下一个非零数该住哪儿" | 模式：双指针·快慢指针

## 题面

给定一个数组 `nums`，编写一个函数将所有 `0` 移动到数组的末尾，同时**保持非零元素的相对顺序**。

请注意，必须**在不复制数组的情况下**原地对数组进行操作。

```text
示例 1：nums = [0,1,0,3,12] → 之后 nums 应为 [1,3,12,0,0]
示例 2：nums = [0]          → 之后 nums 应为 [0]
```

约束：`1 <= nums.length <= 10^4`，`-2^31 <= nums[i] <= 2^31 - 1`。**进阶：你能尽量减少完成的操作次数吗？**

```python
class Solution:
    def moveZeroes(self, nums: list[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
```

<details><summary>💡 提示第 1 档·方向（点开前先自己想 3 分钟）</summary>

想象你扫过一排盒子，要把所有空盒子（零）赶到队尾，非空的按原顺序往前排。一个人边扫边问自己：**到现在为止，我见过的第几个非零数？它应该住在第几个格子？**——这个"第几个格子"就是关键。扫描过程中不断把非零数搬到它该住的格子里，扫完后剩下的格子填什么？
</details>

<details><summary>💡 提示第 2 档·模式点名</summary>

快慢双指针：slow 管"下一个非零数该去的位置"，fast 负责从头到尾扫描。两个指针从同一起点出发，fast 永远跑在前面（或并排），遇到非零数就把数交给 slow。
</details>

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. slow 从 0 出发，含义是"下一个非零数该住进 slow 这个格子"；
2. fast 也从 0 出发，一路往右扫每个数；
3. fast 扫到的数不是零：把它覆盖到 slow 的格子（如果 fast 和 slow 不在同一格，slow 那格现在是零或已被搬走，覆盖是安全的），然后 slow 往右挪一格；
4. 是零：什么都不做，只有 fast 往右走；
5. fast 扫完全数组后，slow 停在"非零区"的下一个空位；
6. 从 slow 走到数组末尾，全部填 0——因为原来的零都被甩在后面了；
7. 注意：从 slow 到末尾补零这一步不能漏，覆盖版把零弄丢了，得手动补回来。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：fast 扫整个数组，一个不漏。
2. 记录什么：slow 下标，表示"非零数已经填满到 slow 前一格，slow 是下一个空位"。
3. 怎么判断/返回：fast 遇到非零就 `nums[slow] = nums[fast]` 并 slow 前进；扫完后从 slow 到末尾全填 0。原地改，无返回值。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

**解法 A·覆盖+补零版（先掌握这个）**

```python
class Solution:
    def moveZeroes(self, nums: list[int]) -> None:
        slow = 0
        for fast in range(len(nums)):
            if nums[fast] != 0:
                nums[slow] = nums[fast]
                slow += 1
        for i in range(slow, len(nums)):
            nums[i] = 0
```

- 第 3 行 `slow = 0` —— 空位指针就位：从 0 开始，意思是"目前一个非零数都没住进来，第 0 格是下一个空位"。
- 第 4 行 `for fast in range(len(nums))` —— fast 负责把数组从头到尾扫一遍，一个不漏。
- 第 5 行 `if nums[fast] != 0:` —— 只对非零数动手，零直接放过。反过来会怎样：条件写反成 `== 0`，那就是把零往前搬、非零数原地不动，结果完全搞反。
- 第 6 行 `nums[slow] = nums[fast]` —— 把当前非零数搬到它该住的空位。为什么敢覆盖：slow 要么和 fast 同格（中间没出过零，自己抄自己，无害），要么 slow 落后于 fast，中间的格子全是零或已被搬走的东西，覆盖不丢任何非零数。相对顺序也保住了——非零数按 fast 扫到的先后依次入座。
- 第 7 行 `slow += 1` —— 住进来一个，空位指针往右挪一格。
- 第 9 行 `for i in range(slow, len(nums)):` —— 扫完了，slow 到末尾这段就是被腾出来的尾巴。range 从 slow 开始到 `len(nums)` 结束（range 右端开区间，正好不含越界）。
- 第 10 行 `nums[i] = 0` —— 尾巴全部填零。这步**绝不能漏**：覆盖版把原来的零冲掉了，不补的话 `[0,1,0,3,12]` 会变成 `[1,3,12]` 后面跟旧垃圾。写错这步最常见的翻车是把非零数弄丢——比如手滑写成 `nums[i] = nums[slow]`，尾巴被同一个数填满。

**解法 B·原地交换版（进阶要求：零操作次数更少，一次遍历不用补零）**

```python
class Solution:
    def moveZeroes(self, nums: list[int]) -> None:
        slow = 0
        for fast in range(len(nums)):
            if nums[fast] != 0:
                nums[slow], nums[fast] = nums[fast], nums[slow]
                slow += 1
```

- 和 A 的唯一区别：不覆盖，改成交换 slow 和 fast 两个位置的数。这样零被一步步"冒泡"到后面，非零数也各就各位，一次遍历完事，不用第二个循环补零。A 和 B 本质相同：都是"slow 守着非零区的门，fast 见到非零就往门里送"。先用 A 建立直觉，B 是 A 的精装修。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **覆盖版漏补零**：现象——非零数对了但尾巴缺零或残留旧值。病因：`nums[slow] = nums[fast]` 只搬非零数，零不会自己归位。修复：第二个循环从 slow 填到末尾（或直接换解法 B）。
2. **补零边界写错把非零数弄丢**：现象——比如 `[1,2]` 变 `[0,0]`。病因：补零循环写成 `range(len(nums))` 从头填，把前面好不容易搬好的非零数全冲了。修复：起点必须是 `slow`，不是 0。
3. **slow 挪错位置（放进 if 外面）**：现象——非零数中间被零撑开，如 `[1,0,2]` 变 `[1,0,2]` 没动。病因：不管搬没搬东西都挪 slow，空位指针就失去"非零区边界"的含义了。修复：`slow += 1` 必须缩进在 `if` 里面——只有真住进来一个非零数才前进。
4. **想用 `nums.remove(0)` 循环删再 append**：现象——结果看似对但漏元素或顺序乱。病因：边遍历边删会让 fast 跳过刚补位的元素；`remove` 只删**第一个** 0，循环条件还容易写死循环。修复：别边扫边删，用快慢指针搬。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"slow 到底代表什么"——想不清"下一个非零该住哪儿"，两指针就只是两个会动的数。用 `[0,1,0,3,12]` 手推一遍 slow/fast 的落点，卡点就化开。
2. 最容易漏的动作：覆盖版最后的**补零循环**；以及 slow 前进必须锁在 if 里面。
3. 为什么快：暴力解是"扫到一个零就把后面全体前移一格"（O(n²)，最坏全零时每个零都牵动整个数组搬家）；快慢指针每个数只被 fast 摸一次、最多被 slow 写一次，整体 O(n)，空间 O(1)。
4. 信号词："原地""保持相对顺序""把某类元素挪到一端"→ 快慢双指针。凡是"分区"题（把数组劈成两半，各自性质不同），先想 slow 守边界。
5. 变式：把偶数挪到前面、奇数留在后面（同骨架，条件换 `== 0` 为 `x % 2 == 0`）；排序数组去重（LC26，slow 守"已确认不重复区的门"，一模一样的分区思想）。
</details>
