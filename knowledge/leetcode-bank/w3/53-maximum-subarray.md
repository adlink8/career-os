# LC53 最大子数组和（简单）

> 一句话考点：找一段连续数字，加起来最大 | 模式：一次遍历 + 滚动变量（前缀和贪心：cur 算"拖着走合算吗"）

## 题面

给你一个整数数组 `nums`，请你找出一个具有最大和的**连续子数组**（子数组最少包含一个元素），返回其最大和。子数组是数组中的一个连续部分。

```text
示例 1：nums = [-2,1,-3,4,-1,2,1,-5,4] → 6   （连续子数组 [4,-1,2,1] 的和最大）
示例 2：nums = [1]                      → 1
示例 3：nums = [5,4,-1,7,8]             → 23 （整个数组加起来最大）
```

约束：`1 <= nums.length <= 10^5`，`-10^4 <= nums[i] <= 10^4`。

**进阶**：如果你已经实现复杂度为 O(n) 的解法，尝试使用更为精妙的**分治法**求解——进阶不要求，掌握本卷的 O(n) 即可。

<details><summary>💡 提示第 1 档·方向（点开前先自己想 3 分钟）</summary>

从左往右挨个加数，手里维持一个"目前这段的累计和"。每拿到一个新数之前想一个问题：**前面攒下的这个累计和，是包袱还是本钱？**如果它已经是负的了，那把它带在身上只会拖累后面的数——不如把它扔掉，从当前这个数重新开始攒。全程另外记一个"历史最高累计"。
</details>

<details><summary>💡 提示第 2 档·模式点名</summary>

一次遍历 + 两个滚动变量：cur 表示"含当前数、以当前位置结尾的最大累计和"，total 表示"历史最高"。每走一步先决定是累加还是重开，再用 cur 刷新 total。这是动态规划最朴素的形态，但不啃名词，记住"负累计是包袱"这个判断就够了。
</details>

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. 两个变量都从第一个数出发：cur = 第一个数，total = 第一个数（**不要从 0 出发**，理由见坑清单）；
2. 从第二个数开始逐个走：cur = max(前一个 cur + 当前数, 当前数)——翻译过来就是"前面攒的是正本钱就接着攒，是负包袱就扔掉重开"；
3. 每走完一步，total = max(total, cur)，把历史最高记下来；
4. 全部走完，交 total。
5. 判断时机：先更新 cur，再用 cur 刷新 total——顺序不能反，否则当前数还没参与比较。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：nums 从左到右一遍，一个数一个数走。
2. 记录什么：cur（以当前位置结尾的最大累计和，可能是新开的一段）和 total（历史最高）。
3. 怎么判断/返回：每步 cur 在"接着攒"和"扔掉重开"里挑大的，顺手刷新 total；最后返回 total。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

```python
class Solution:
    def maxSubArray(self, nums: list[int]) -> int:
        cur = nums[0]
        total = nums[0]
        for i in range(1, len(nums)):
            cur = max(cur + nums[i], nums[i])
            total = max(total, cur)
        return total
```

- 第 3 行 `cur = nums[0]` —— 以"第一个数"作为出发的累计，不是 0。反过来会怎样：cur 从 0 出发，全负数组如 `[-3,-1,-2]` 会被算成"什么都不选 = 0"，返回 0，而正确答案是 -1（至少要选一个数）。
- 第 4 行 `total = nums[0]` —— 历史最高也从第一个数出发，同样防全负数组。写成 `total = 0` 是本题最经典的错误答案来源。
- 第 5 行 `for i in range(1, len(nums)):` —— 从第二个数开始走（第一个数已经在 cur/total 里了），range 起点是 1 不是 0，否则第一个数被算两遍。
- 第 6 行 `cur = max(cur + nums[i], nums[i])` —— 全题的决策核心：`cur + nums[i]` 是"接着攒"（前面的累计是本钱），`nums[i]` 是"扔掉重开"（前面的累计是负包袱，带着它不如不带）。max 挑合算的那条路。例如走到示例 1 的 4 时，前面 cur 是负的，max 自动选了"只拿 4 重开"。
- 第 7 行 `total = max(total, cur)` —— **用刚更新的 cur 刷新历史最高**。必须在 cur 更新之后：cur 此刻是"以 i 结尾的最优"，只有它才有资格参选。这行如果写在第 6 行前面，当前数根本没进比较，答案会漏。
- 第 8 行 `return total` —— 交历史最高。注意返回的是 total 不是 cur：cur 只是"以最后一个数结尾"的累计，最大那段可能早就出现在中间。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **cur / total 初始化成 0**：现象——全负数组（如 `[-3,-1,-2]`）返回 0，正确是 -1。病因：题面规定子数组至少含一个元素，"空着不选"不是合法答案。修复：都用 `nums[0]` 初始化。
2. **刷新 total 的时机不对**：现象——示例 1 返回 4 而不是 6。病因：在 cur 更新前就 `total = max(total, cur)`，当前数没参与。修复：先更新 cur，再刷新 total，两行顺序锁死。
3. **range(1, ...) 写成 range(0, ...)**：现象——示例 3 返回 28（第一个数被加两遍）。病因：起点忘了 1。修复：循环从第二个数开始。
4. **最后 return cur**：现象——最大和出现在中段时答案偏小。病因：cur 只代表"以末尾结尾"的局部最优。修复：返回 total。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"想到不会写"——知道要挨个加，但拿不准"什么时候重新开始"。答案就藏在"负累计是包袱"这一句里。
2. 最容易漏的动作：total 用 `nums[0]` 而不是 0 初始化（全负用例一击致命）。
3. 为什么这么解：暴力法枚举所有起点终点、每段求和是 O(n²)，配上快速求和也要先建前缀和表占 O(n) 空间；滚动变量版只走一遍，每步 O(1) 决策，O(n) 时间、O(1) 空间——因为它抓住了本质：到每个位置时，最优答案只依赖"前一个位置的最优累计"，不需要知道更早的全部历史。
4. 信号词："连续子数组""最大和"→ 滚动变量贪心（或动规）；注意"连续"意味着不能跳着选，这排除了"挑所有正数相加"的歪解。
5. 变式：返回最大和的那段本身而不是和？多记一个起点，cur 重开时更新起点。环形数组的最大子数组和（LC918）？拆成"不跨界"和"跨界"两种情况讨论。
</details>
