# LC206 反转链表（简单）

> 一句话考点：把单向链表的箭头全部掉头 | 模式：链表三指针（prev / cur / next）

## 题面

给你单链表的头节点 `head`，请你反转链表，并返回反转后的链表。

**先认识一下链表长什么样**：链表的每个节点是一个"快递盒"，盒子里装着两样东西——
1. 一个值（`val`，比如数字 3）；
2. **下一家的地址**（`next`，指着下一个盒子在哪）。

`cur.next` 的意思就是"打开 cur 这个盒子，看它里面写的下一家地址"。整条链表没有下标、不能 `nums[5]` 那样跳着取，你只能从第一个盒子开始，顺着地址一家一家摸过去。`head` 就是第一家的地址。反转链表 = 把每条"指向下一家"的箭头**调转方向**指回前一家，让原来的尾家变成新头家。

```text
示例 1：head = [1,2,3,4,5] → [5,4,3,2,1]
示例 2：head = [1,2]       → [2,1]
示例 3：head = []          → []
```

约束：链表节点数范围是 `[0, 5000]`，`-5000 <= Node.val <= 5000`。

<details><summary>💡 提示第 1 档·方向（点开前先自己想 3 分钟）</summary>

想象你站在一排快递盒前，要手工把每个盒子上的"下一家地址"改成"上一家的地址"。麻烦在哪？盒子上的地址是印刷的，你一改，通往后面的路就断了——所以动手改之前，你必须先把"原来通往下一家的地址"抄到手心里，否则后面整排盒子就找不到了。
</details>

<details><summary>💡 提示第 2 档·模式点名</summary>

链表三指针：你需要三个"手"——一个指着已经掉头完成的那段的开头，一个指着正在处理的盒子，一个临时手专门用来抄"下一家地址"。这是链表题的通用起手式，比数组题的循环变量多一个，因为你改箭头就是拆路。
</details>

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. 三个变量：prev（已反转段的头，起步为空）、cur（当前盒子，起步为原头家）、next（临时手，现在是空的）；
2. 只要 cur 还有盒子在手，循环三步：先抄——next 记下 cur 的下一家；再掉头——cur 的地址改指 prev；后移动——prev 挪到 cur，cur 挪到 next；
3. 循环结束时 cur 已经拿空了（越过最后一个盒子），prev 正指着反转后链表的头，交 prev。
4. 注意交卷的必须是 prev 不是 cur——cur 出循环时是空的。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：从 head 开始顺链表一家一家走，cur 是当前盒子。
2. 记录什么：prev（前面已经掉完头的那段的头）+ next（改箭头前先抄下的下一家地址）。
3. 怎么判断/返回：cur 走空（None）就停；返回 prev，它是新链表的头。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

```python
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev = None
        cur = head
        while cur:
            next = cur.next
            cur.next = prev
            prev = cur
            cur = next
        return prev
```

- 第 3 行 `prev = None` —— 已反转段一开始是空的，prev 举着"空地址"。第一个盒子掉头后要指向它，正好当新尾巴。
- 第 4 行 `cur = head` —— cur 从原头家出发，是正在处理的盒子。
- 第 5 行 `while cur:` —— 手里还有盒子就干活。cur 变成 None 的那一刻，说明所有盒子都处理完了。空链表（head=[]）时第一次判断就不过，直接走第 10 行，安全。
- 第 6 行 `next = cur.next` —— **先抄下一家地址**。这行是全题的命门：下一行要改 cur 的箭头，如果先改再抄，下一家就永远找不到了（断链）。反过来会怎样：先写 `cur.next = prev` 再抄，等于把路标擦了才想起来没记路线，后半条链直接失踪。
- 第 7 行 `cur.next = prev` —— **箭头掉头**。cur 从"指向下一家"改成"指回上一家"（现在是 prev）。
- 第 8 行 `prev = cur` —— prev 前进一格，站稳刚掉完头的盒子。
- 第 9 行 `cur = next` —— cur 拿着抄好的地址前进一格，去处理下一个盒子。注意必须用抄在手里的 next 挪，不能问 cur 要了（cur 的箭头已经掉头指回去了）。
- 第 10 行 `return prev` —— 循环结束时 cur 是 None，prev 才是新链表的头。写 return cur 会交一个空链表上去。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **先掉头后抄地址（断链）**：现象——返回的链表只有一半甚至一个节点。病因：`cur.next = prev` 写在 `next = cur.next` 前面，下一家的地址被覆盖丢失。修复：死记顺序"先抄、再掉头、后挪"。
2. **return cur 不是 prev**：现象——返回空。病因：出循环时 cur 已经走过了最后一个盒子（是 None），站在新头家的是 prev。修复：返回 prev。
3. **把链表当数组写 `head[0]`**：现象——报 `TypeError`。病因：链表没有下标，只能顺着 `next` 摸。修复：用 `while cur` + `cur.next` 逐家走。
4. **改箭头和挪指针顺序混乱**：现象——死循环（链成个圈绕不出去）或提前断链。病因：四步之间有严格依赖。修复：固定成模板，四行一个字不改地背下来。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"想到不会写"——知道要掉头，但一动手就断链，因为没意识到"改箭头会毁路"。
2. 最容易漏的动作：改箭头**之前先抄 next**。这是本模式的灵魂步。
3. 为什么这么解：暴力法是"把值读进数组、反转、再倒回链表"，两趟扫描 O(n) 时间但占 O(n) 空间，且需要重新建链容易写错；三指针一趟走完，O(n) 时间、O(1) 空间——只挪三个手，不建任何新盒子。
4. 信号词："反转链表""倒序"→ 三指针掉头；"链表"这个词本身就该让你想到不能下标访问、只能顺 next 走。
5. 变式：反转前 n 个节点（LC92 反转链表 II）？同一套掉头术，多记一个第 n+1 处的接口。回文链表（LC234）？先反转后半段再对比，还是这招。
</details>
