# LC15 三数之和（中等·试水）

> ⚠️ 这题属于试水加餐：easy 全部通关后才做，卡住超时可看解析不丢人。
>
> 一句话考点：排序后固定一个数，剩下两个用首尾双指针夹出来——Two Sum 的进阶版 | 模式：排序 + 固定一个数 + 首尾双指针

## 题面

给你一个整数数组 `nums`，判断是否存在三元组 `[nums[i], nums[j], nums[k]]` 满足 `i != j`、`i != k`、`j != k`，同时还满足 `nums[i] + nums[j] + nums[k] == 0`。请你返回所有和为 0 且**不重复**的三元组。注意：答案中不可以包含重复的三元组。

```text
示例 1：nums = [-1,0,1,2,-1,-4] → [[-1,-1,2],[-1,0,1]]
示例 2：nums = [0,1,1]          → []
        （不存在三元组和为 0）
示例 3：nums = [0,0,0]          → [[0,0,0]]
        （唯一的三元组）
```

约束：`3 <= nums.length <= 3000`，`-10^5 <= nums[i] <= 10^5`。

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
```

<details><summary>💡 提示第 1 档·方向（点开前先自己想 3 分钟）</summary>

Two Sum 你做过：找一个数，问"它的搭档在不在"。现在是找三个数，直接问"两个搭档的组合"就乱了。想一个降维办法：能不能**钉死其中一个数**，让问题退化成你已经会做的"两数之和"？另外，乱序数组上找搭档很费劲——先给数组排个队，搭档关系会不会变得更好找？
</details>

<details><summary>💡 提示第 2 档·模式点名</summary>

排序 + 固定一个数 + 首尾双指针。外层循环把每个数轮流当"第一个数"，内层在它右边的区间里放一左一右两只手：和大了收右手、和小了抬左手、正好收网。这题真正的考点是**去重**——三处都要防重复：固定数、左手、右手。
</details>

<details><summary>💡 提示第 3 档·步骤点破（卡死 20 分钟才许开）</summary>

1. 先排序（一切的前提）；
2. 外层从第一个数开始，轮流固定第一个数 k；小剪枝：如果这个数已经大于 0，后面全是正数不可能凑出 0，直接收工；
3. 跳重复第一处：如果这个数和上一个固定数相同，跳过（同样的第一个数已经找过一轮了）；
4. 内层在 k 右边放左右两只手：三数之和大于 0 → 右手往左收；小于 0 → 左手往右抬；等于 0 → 记下这组，然后**跳重复第二、三处**：左手跳过相邻相同的、右手跳过相邻相同的，最后两只手再各挪一格错开，继续找；
5. 外层走完，交出所有记下的三元组。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：排序后，外层逐个固定第一个数 k；内层在 k 右侧用左右双指针扫。
2. 记录什么：结果列表 result；比较时只用 k、左指针、右指针三处的值之和。
3. 怎么判断/返回：和为 0 记一组并双端跳重复；和偏大收右手、偏小抬左手；外层走完返回 result。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        nums.sort()
        result = []
        for k in range(len(nums) - 2):
            if nums[k] > 0:
                break
            if k > 0 and nums[k] == nums[k - 1]:
                continue
            left, right = k + 1, len(nums) - 1
            while left < right:
                s = nums[k] + nums[left] + nums[right]
                if s < 0:
                    left += 1
                elif s > 0:
                    right -= 1
                else:
                    result.append([nums[k], nums[left], nums[right]])
                    while left < right and nums[left] == nums[left + 1]:
                        left += 1
                    while left < right and nums[right] == nums[right - 1]:
                        right -= 1
                    left += 1
                    right -= 1
        return result
```

- 第 3 行 `nums.sort()` —— **排序，一切的前提**。排序后：①可以首尾双指针夹逼（大了收小的、小了抬大的有方向感）；②相同的数排在一起，去重只需看邻居；③k 剪枝才成立。不排序这套全塌。
- 第 4 行 `result = []` —— 空结果筐。
- 第 5 行 `for k in range(len(nums) - 2):` —— 外层固定第一个数，最多到倒数第三个（右边要留两个位置给搭档）。
- 第 6~7 行 `if nums[k] > 0: break` —— **剪枝**：排好序后 k 后面的数都 >= 它，第一个数已经是正数，三个正数加不出 0，整场结束。反过来会怎样：漏了这行不会错，但 3000 个数的用例会慢一截。
- 第 8~9 行 `if k > 0 and nums[k] == nums[k-1]: continue` —— **跳重复第一处**：这个数当"第一个数"的活上一轮已经干过了，再干只会交出重复三元组。`k > 0` 防止第一个数就跟自己（越界）比。
- 第 10 行 `left, right = k + 1, len(nums) - 1` —— 两只手站上 k 右侧区间的两端（搭档只能从 k 后面找，防止和前面的 k 重复组合）。
- 第 11 行 `while left < right:` —— 两手没碰头就继续夹。碰头说明这段区间找完了。
- 第 12 行 `s = ...` —— 三处值的和。
- 第 13~14 行 `if s < 0: left += 1` —— 和偏小，要更大的数：左手右抬（右边的数更大）。
- 第 15~16 行 `elif s > 0: right -= 1` —— 和偏大，收右手（右边的数更大，收掉它和变小）。
- 第 17 行 `else:` + 第 18 行 —— 和为 0，记下这组进结果筐。
- 第 19~23 行 —— **跳重复第二、三处**：记完一组后，左手把相邻相同的全跳过、右手同理；最后 `left += 1 / right -= 1` 两手各再错开一格（跳完停在"最后一个相同的"上，还得挪出去）。反过来会怎样：漏了这两个 while，`[-2,0,0,2,2]` 会交出 `[-2,0,2]` 两次；漏了最后的各挪一格，下一轮和不变，死循环。while 里的 `left < right` 防的是 `[0,0,0]` 这种跳重时两手越过头的边界炸裂。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **不去重，交出重复三元组**：现象——示例 1 返回 `[[-1,0,1],[-1,-1,2],[-1,0,1]]` 判错。病因：只顾找答案没管去重。修复：三处跳重复——固定数看邻居、命中后左右手各跳邻居。
2. **命中后忘了两手各挪一格**：现象——死循环卡死。病因：记完一组两手不动，下一轮 s 还是 0，无限记同一组。修复：跳重循环之后必须 `left += 1` 和 `right -= 1`。
3. **跳重循环漏写 `left < right`**：现象——`[0,0,0]` 报越界。病因：一路跳相同值时两手可能穿过彼此。修复：每个跳重 while 都带 `left < right` 守门。
4. **双指针挪错方向**：现象——答案漏或超时。病因：s 偏大该收右手却抬了左手（越抬越偏）。修复：记住"右边是大数端"——偏大收右、偏小抬左。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"想到不会写"的降维处——知道和 Two Sum 有关，但想不到"固定一个数后退化成两数之和"，更想不到哈希路线会卡在去重上。
2. 最容易漏的动作：命中后左右手的跳重 + 各挪一格（不漏它答案必错或死循环）。
3. 为什么这么解：哈希一把梭（对每个数问"另外两个数的组合见过没"）找答案本身能做到 O(n²) 甚至更快，但**去重极难**——同一个三元组会以三种排列被找到三次，你得对每个结果排序再塞进集合查重，又乱又费；排序 + 双指针法去重只需看邻居（相同的数天然挨着），整体 O(n²) 时间（排序 O(n log n) 可忽略）、O(1) 额外空间（不算结果），代码也短得多。**条件复杂时，"让结构帮你免查重"比"先找全再筛"稳。**
4. 信号词："三个数的和等于定值"→ 排序 + 固定一个 + 双指针；"不重复的（元组/三元组）"→ 立刻警觉去重三连，且优先考虑排序法。
5. 变式：最接近的三数之和（LC16）？骨架原样，把"等于 0"换成"记录离目标最近的 s"。四数之和（LC18）？外面再套一层固定数，变成两轮降维。
</details>

<details><summary>🔗 迁移与同模式下一题</summary>

本题是"排序 + 双指针"家族的正式拜师题：LC11 盛最多水的容器是纯双指针（少了固定数的角色），LC16/18 是同骨架的换皮与套娃。之后见到"和为定值 + 不重复"，条件反射应该是：先 sort，再固定，再夹。
</details>
