# LC21 合并两个有序链表（简单）

> 一句话考点：两条排好队的链子，穿成一条仍然排好队的 | 模式：链表双指针 + 哑节点（dummy）

## 题面

将两个升序链表合并为一个新的**升序**链表并返回。新链表是通过拼接给定的两个链表的所有节点组成的。

**复习一下链表**：每个节点是一个快递盒，盒子里装着值 `val` 和下一家地址 `next`。这道题不许"新建一个数组排序"绕过去——要的是**改指针拼链子**：让盒子的箭头重新指向，把两条链串成一条。

```text
示例 1：list1 = [1,2,4], list2 = [1,3,4] → [1,1,2,3,4,4]
示例 2：list1 = [], list2 = []           → []
示例 3：list1 = [], list2 = [0]          → [0]
```

约束：两个链表的节点数目范围是 `[0, 50]`，`-100 <= Node.val <= 100`，两个链表均按**非递减顺序**排列。

<details><summary>💡 提示第 1 档·方向（点开前先自己想 3 分钟）</summary>

想象两摞已经从小到大码好的扑克牌，每次只能看每摞最上面那张。合并的动作其实很土：每次比两张牌，把小的那张抽出来放到新摞上，它所在那摞顺势露出下一张。反复抽，直到有一摞空了——另一摞剩下的整摞直接端过去接上就行（它本来就排好序了）。另外开头有个小尴尬：第一张牌放哪？需要找个"假的开头"先垫着。
</details>

<details><summary>💡 提示第 2 档·模式点名</summary>

链表双指针 + 哑节点（dummy）。双指针负责在两条链上各举一只手比大小；dummy 是一个人造的假开头节点，专门替你解决"谁是新链表第一个节点"这个开头特判——你先接在假开头后面，最后从假开头的下一家交卷。
</details>

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. 造一个假开头盒子（dummy），再造一只手 cur 站在 dummy 上负责接线；
2. 两条链各有一只手 p1、p2，都站在各自第一家；只要两只手都举着盒子：比 val，谁小就把 cur 的下一家接到谁，那只手前移一格；cur 也跟着前移到刚接上的盒子；
3. 有一只手空了，就把 cur 的下一家直接接到另一条没空链的当前位置（整段剩余本来就是有序的）；
4. 交卷：返回 dummy 的下一家，不是 dummy 自己——dummy 是垫脚的假货。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：两条链各一个指针 p1 / p2，同时走；接线手 cur 跟在结果链末尾。
2. 记录什么：dummy 假开头 + cur 当前接线位置。
3. 怎么判断/返回：p1 或 p2 走空就停循环，把另一条剩余整段接到 cur.next；返回 dummy.next。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

```python
class Solution:
    def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)
        cur = dummy
        p1, p2 = list1, list2
        while p1 and p2:
            if p1.val <= p2.val:
                cur.next = p1
                p1 = p1.next
            else:
                cur.next = p2
                p2 = p2.next
            cur = cur.next
        cur.next = p1 if p1 else p2
        return dummy.next
```

- 第 4 行 `dummy = ListNode(0)` —— 造假开头。作用要讲透：没有它，你得单独写一段"先比出第一条链的头当结果头，再开始接"的开头特判；有了它，所有盒子的接线动作完全一样，写一遍就行。它里面的 0 没有意义，最后会被甩掉。
- 第 5 行 `cur = dummy` —— cur 是接线手，永远站在结果链最后一个盒子上，负责"下一家接到谁"。
- 第 6 行 `p1, p2 = list1, list2` —— 两只比大小的手，分别站上两条链的第一家。不直接用 list1/list2 走，是为了保住原始头地址（虽然本题最后没用到原始头，但养成不动输入的习惯）。
- 第 7 行 `while p1 and p2:` —— 两边都还有盒子才比；任何一边空了就出循环。
- 第 8~12 行 —— 比大小、接小的：p1 小（含相等，等价）就把 cur.next 指向 p1，p1 前移；否则接 p2。接线的同时原链箭头没被破坏——只是新链"借用"了这些盒子。
- 第 13 行 `cur = cur.next` —— 接线手前移到刚接上的盒子，准备下一轮接线。这行在 if/else **外面**（缩进与 if 平齐）——不管接的是谁，cur 都要前进。写进 if/else 各一份也行，但漏写一边就是 bug。
- 第 14 行 `cur.next = p1 if p1 else p2` —— **接剩余尾巴**。一条链走空后，另一条剩下的整段本来就有序，直接接上。反过来会怎样：漏掉这行，结果链会在剩余内容开始的地方断掉，输出缺一截。
- 第 15 行 `return dummy.next` —— 交卷交的是假开头的**下一家**（真头）。返回 dummy 自己，输出会多出一个值是 0 的假盒子。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **忘记接剩余尾巴**：现象——输出链在中间断掉，后面少一截。病因：while 结束只顾交卷，忘了没空的那条还有整段。修复：出循环后一句"把没空的接到 cur.next"。
2. **return dummy 不是 dummy.next**：现象——输出开头多一个 0。病因：dummy 是垫脚的假节点。修复：返回 dummy.next。
3. **只用 list1/list2 直接走、不用 dummy**：现象——头节点特判写得手忙脚乱，空链用例崩。病因：没意识到"结果链第一个节点来自哪条链"需要特判。修复：一律 dummy 起手。
4. **cur 忘了前移**：现象——死循环（每次都往同一个盒子后面接线）。病因：cur 停在原地反复覆盖 cur.next。修复：每轮接线后 `cur = cur.next`。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"开头接不上"——不知道结果链第一个节点是哪家的，dummy 就是专门收掉这个卡点的。
2. 最容易漏的动作：循环结束后接剩余尾巴。
3. 为什么这么解：暴力法是"把两条链的值全倒进数组、排序、再重建链表"，O((n+m)log(n+m)) 时间还要重建盒子；双指针版本利用"两边已有序"这个题面送上门的条件，每轮 O(1) 就定下一个盒子，整体 O(n+m) 时间、O(1) 空间——**原题已排序的信息不用是浪费**。
4. 信号词："合并两个有序的"→ 双指针逐个比 + dummy；"升序/非递减"这个词就是在暗示你利用顺序，别排序。
5. 变式：合并 k 条有序链表（LC23）？把"两两比"换成"每轮在 k 个头里挑最小"或两两归并。数组版的有序合并（归并排序的核心步骤）？同一个比法。
</details>
