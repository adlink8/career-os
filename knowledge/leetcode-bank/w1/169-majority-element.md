# LC169 多数元素（简单）

> 一句话考点：数谁出现超过一半 | 模式：哈希计数（主） / 摩尔投票（进一步）

## 题面

给定一个大小为 `n` 的数组 `nums`，返回其中的**多数元素**。多数元素是指在数组中出现次数**大于** `⌊n/2⌋` 的元素。你可以假设数组是非空的，并且给定的数组总是存在多数元素。

```text
示例 1：nums = [3,2,3]        → 3
示例 2：nums = [2,2,1,1,1,2,2] → 2
```

约束：`n == nums.length`，`1 <= n <= 5 * 10^4`，`-10^9 <= nums[i] <= 10^9`。

进阶：尝试设计时间复杂度为 O(n)、空间复杂度为 O(1) 的算法解决此问题。

```python
class Solution:
    def majorityElement(self, nums: list[int]) -> int:
```

用哈希家族的 dict（键值对柜子）当**计数账本**：键是数字，值是它出现的次数，和 LC242 一模一样的记账手法。最后从账本里找值最大的那格。
</details>

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. 造一个空账本；
2. 逐个数组里的数，每个数账本上的次数加一（没记过的当零开始）；
3. 记完账，遍历账本所有格子，盯住"值最大的那格"——用一个大口袋先随便装第一个格子，然后逐个比较换更大；
4. 交出值最大那格的键。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：数组 nums 的每个数。
2. 记录什么：一个 dict，键是数，值是出现次数；另留一个变量记"目前见过的最大次数对应的数"。
3. 怎么判断/返回：记完账后找值最大的格子，返回它的键。题目保证多数元素存在，所以票数第一的就是答案。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

**解法 A·计数账本版（先掌握这个）**

```python
class Solution:
    def majorityElement(self, nums: list[int]) -> int:
        freq = {}
        best = nums[0]
        for n in nums:
            freq[n] = freq.get(n, 0) + 1
            if freq[n] > freq[best]:
                best = n
        return best
```

- 第 3 行 `freq = {}` —— 空账本，键放数、值放次数，和 LC242 同款。
- 第 4 行 `best = nums[0]` —— 大口袋先随便装第一个数当"暂定冠军"。取 `nums[0]` 是安全的（约束保证数组非空）；写 `best = None` 也行，但后面比较前要多判一次空。
- 第 5-6 行 `for n in nums: freq[n] = freq.get(n, 0) + 1` —— 边走边记账，get 兜底防 KeyError，和上一题完全同一个动作。
- 第 7 行 `if freq[n] > freq[best]: best = n` —— 刚记完这笔，顺手比一比：这个数的票数超过暂定冠军，就换它上位。不用等记完账再单独扫一遍账本，一趟内两件事全干完。反过来写 `freq[n] >= freq[best]` 也能过（多数元素必是唯一冠军），但 `>` 意图更准。
- 第 9 行 `return best` —— 在 for **外面**，全部记完账才交卷。
- 顺带一提：账本版天然也能处理"不存在多数元素"的输入——最后验一下 `freq[best] > len(nums)//2` 即可，本题题目保证存在，可省。

**解法 B·摩尔投票版（进阶·O(1) 空间，懂了 A 再看）**

```python
class Solution:
    def majorityElement(self, nums: list[int]) -> int:
        candidate = None
        count = 0
        for n in nums:
            if count == 0:
                candidate = n
            count += 1 if n == candidate else -1
        return candidate
```

- 思路：让候选人和不同阵营"贴身对拼"，一换一抵消。多数元素超过一半，所以别人怎么抵都抵不完它。count 减到 0 说明当前候选人已被抵光，换下一个数当新候选人。
- 局限：**只在"多数元素保证存在"时成立**——不保证存在的话（如 [1,2,3] 返回 3）答案是错的，得再加一遍验证。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **`freq[c] = freq[c] + 1` KeyError**：现象——第一个新数就崩。病因：字典里没有的键不能直接读。修复：`freq.get(n, 0) + 1`。
2. **`best` 初始化为 None 后直接比较**：现象——`TypeError: '>' not supported between NoneType and int`。病因：None 没法参与大小比较。修复：用 `nums[0]` 初始化，或比较前先判 None。
3. **找最大值时键值搞反**：现象——返回了最大次数（比如 3）而不是那个数。病因：`max(freq.values())` 拿到的是票数不是人。修复：要返回键——用 `max(freq, key=freq.get)` 或边走边记 best。
4. **return 写进循环**：现象——第一个数票数暂时领先就提前交卷。病因：还没记完账冠军可能被反超。修复：交卷放循环外。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"记完账不会找最大值的键"——`max(freq.values())` 拿到的是票数，要的是键。
2. 最容易漏的动作：记账时同步更新 best（很多初学者记完账再单独扫一遍，多做一趟，也对但绕）。
3. 为什么快：暴力是每个数重扫全数组数它的次数，O(n²)；账本一趟记完、查询哈希直达，O(n)。一句话：把"每个数都重新数一遍"变成"一遍走完所有数只记一次账"。
4. 信号词："出现超过一半""多数""众数"→ dict 计数；进阶再提"空间 O(1)"→ 摩尔投票。
5. 变式：找所有出现超过 n/3 次的元素？（LC229，至多两个，账本要两张或摩尔投票变体。）不存在多数元素要返回 -1？（记账后验证次数是否过半。）
</details>
