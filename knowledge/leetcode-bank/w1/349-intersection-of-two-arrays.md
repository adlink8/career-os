# LC349 两个数组的交集（简单）

> 一句话考点：两边都查"见过没"，还要掐掉重复 | 模式：哈希（双 set/查询+结果两个容器）

## 题面

给定两个数组 `nums1` 和 `nums2`，返回它们的**交集**。输出结果中的每个元素必须是**唯一**的（不含重复），可以不考虑输出结果的顺序。

```text
示例 1：nums1 = [1,2,2,1], nums2 = [2,2]     → [2]
示例 2：nums1 = [4,9,5],   nums2 = [9,4,9,8,4] → [9,4]（[4,9] 也对）
```

约束：`1 <= nums1.length, nums2.length <= 1000`，`0 <= nums1[i], nums2[i] <= 1000`。

```python
class Solution:
    def intersection(self, nums1: list[int], nums2: list[int]) -> list[int]:
```

<details><summary>💡 提示第 1 档·方向（点开前先自己想 3 分钟）</summary>

你在其中一个数组里挨个数，每拿一个数，只问一件事：**它在另一个数组里出现过吗？**"在另一个数组里找东西"这个动作如果每次都从头翻页，慢——你手上已经有让"找"变成"一问就答"的家伙了。另一个麻烦：交出来的答案里同一个数不能出现两次，这个"只计入一遍"你在 LC217 刚练过（先查后存），或者干脆在**源头**就让每个数只走一遍。
</details>

<details><summary>💡 提示第 2 档·模式点名</summary>

哈希家族，两处用：①把一个数组整体倒进 set，让"在不在"变成查一次表；②结果装进 list，装之前查重，或者干脆遍历 set 让重复在源头消失。注意需要**两个容器**：查询容器和结果容器。
</details>

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. 把第一个数组整体倒进一个 set（查询用）；
2. 造一个空 list（结果用）；
3. 逐个数第二个数组（建议先把它也倒成 set，重复数就只走一遍）；
4. 每个数先查第 1 步的 set——在，就装进结果 list；
5. 循环全部走完，把结果 list 交出去（return 在循环外面）。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：遍历 nums2（建议先 `set(nums2)` 去重，重复数只走一遍）。
2. 记录什么：两个容器——`s = set(nums1)` 管查询；`res = []` 管结果。
3. 怎么判断/返回：每个数 `if i in s:` 命中就 `res.append(i)`；循环走完 `return res`。遍历侧已去重，res 天生不重。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

```python
class Solution:
    def intersection(self, nums1: list[int], nums2: list[int]) -> list[int]:
        s = set(nums1)
        res = []
        for i in set(nums2):
            if i in s:
                res.append(i)
        return res
```

- 第 3 行 `s = set(nums1)` —— 把整个 nums1 倒进"自动去重的袋子"，从此"这个数在 nums1 里吗"从翻页 O(m) 变哈希直达 O(1)。注意写法：`s = set(nums1)` 是"名字在左、内容在右"，`set() = nums1` 是把函数调用当名字，语法直接报错。
- 第 4 行 `res = []` —— 结果容器，和查询容器**各司其职**。别把两个搅在一起：往 s 里 add 会污染查询源，后面查的就不是"纯 nums1"了。
- 第 5 行 `for i in set(nums2):` —— 本题妙手：遍历目标也转成 set。一石二鸟——nums2 里重复的数只走一遍（源头去重，res 天生不重），扫描也更省。反过来只转一个数组也正确，但 res 就需要自己防重。
- 第 6 行 `if i in s:` —— 唯一的判断：当前数在 nums1 的袋子里吗？哈希直达 O(1)。
- 第 7 行 `res.append(i)` —— 命中才装。这行缩进必须在 if 里面：挪出去就变成"不管中没中都装"，结果就不是交集了。动词是 append（放入），不是 return（送出门）。
- 第 8 行 `return res` —— 和 for 平齐（循环外）。要装的是**所有**命中，所以必须收齐才交卷；写在 if 里=找到第一个就下班。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **容器打架**：定义的 set 没起名、循环里用另一个名字（变量名从上题串门）。修复：一个东西从出生到用完一个名字，动手前先列"我有几个容器"。
2. **return 写进 if/循环**：现象——只返回一个数或提前交卷。病因：return 是终止返回，不是收集。修复：装用 append，收齐后循环外 return。
3. **`set() = nums1` 赋值反向**：现象——`SyntaxError: cannot assign to function call`。病因：`=` 左边必须是变量名。修复：`s = set(nums1)`。
4. **结果不重没保障**：遍历原始 nums2 且 res 不查重 → 输出带重复。修复：遍历 `set(nums2)`（源头去重，推荐）或装之前 `if i not in res`（多一层 O(n) 查，不推荐但正确）。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"输出必须唯一"没处理——题面"唯一"两个字就是信号。
2. 最容易漏的动作：两个容器分开（查询的 set 和结果的 list 各管各的）。
3. 为什么快：暴力是 nums1 每个数和 nums2 所有数两两比 O(n×m)，命中还可能装重；set 把每次"在不在"压到 O(1)，整体 O(n+m)。空间换时间，第三次见它了。
4. 信号词："交集""两边都有""输出唯一"→ 哈希（查询+去重双用途）。
5. 变式：求并集？两个 set 合一起。求"只在 nums1 出现过"的数（差集）？遍历时查另一个 set 不在的。set 自带 `&`、`|`、`-` 运算符干这三件事，通关后试一行版。
</details>
