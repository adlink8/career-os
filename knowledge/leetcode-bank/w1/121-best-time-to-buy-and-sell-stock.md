# LC121 买卖股票的最佳时机（简单）

> 一句话考点：一路走一路记"历史最低价"，顺手算今天卖赚多少 | 模式：一次遍历·记录历史最低

## 题面

给定一个数组 `prices`，它的第 `i` 个元素 `prices[i]` 表示一支给定股票第 `i` 天的价格。你只能选择**某一天**买入这只股票，并选择在**未来的某一个不同的日子**卖出该股票。设计一个算法来计算你所能获取的**最大利润**。如果你不能获取任何利润，返回 `0`。

```text
示例 1：prices = [7,1,5,3,6,4] → 5（第 2 天买 1，第 5 天卖 6，利润 6-1=5；注意 7-1=6 不是答案，因为卖必须在未来）
示例 2：prices = [7,6,4,3,1]   → 0（价格一路跌，怎么买都亏，返回 0）
```

约束：`1 <= prices.length <= 10^5`，`0 <= prices[i] <= 10^4`。

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
```

<details><summary>💡 提示第 1 档·方向（点开前先自己想 3 分钟）</summary>

最笨的办法是每天两两配对试"这天买那天卖"——天数一多就是天文数字的组合。换个视角：站到某一天想卖，我最关心的是**"在我之前的日子里，最低价是多少"**。卖价减去之前那个最低价，就是我今天卖能赚的上限。那你想象从左到右走：手里一直揣着一张纸条记"到今天为止的最低价"，每走一天就问自己"今天卖能赚多少"，记下赚得最多的那次。
</details>

<details><summary>💡 提示第 2 档·模式点名</summary>

一次遍历 + 两个变量的"滚动记录"：一个变量记历史最低价，一个变量记目前最大利润。两个变量在**同一趟循环里同步更新**——不需要任何容器，O(1) 空间。
</details>

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. 先拿第一天的价格当"历史最低价"的初始值，利润初始为 0；
2. 从第二天开始逐天走：每天先算"今天卖能赚多少"（今天价减历史最低），如果比已记录的最大利润高，就刷新它；
3. 然后看今天价是不是比历史最低还低，是就更新历史最低；
4. 全部走完，交最大利润。全程一遍走完，纸条上始终只有两个数。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：prices 逐天过一遍（从第二天起）。
2. 记录什么：两个变量——历史最低价 min_price、目前最大利润 max_profit。
3. 怎么判断/返回：每天先"卖一次试试"（今天价 − 最低价，能刷新最大利润就刷新），再"记今天的最低价"（刷新 min_price）；走完返回最大利润。买在前、卖在后由"先更新利润、后更新最低价"的顺序天然保证。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        min_price = prices[0]
        max_profit = 0
        for price in prices[1:]:
            profit = price - min_price
            if profit > max_profit:
                max_profit = profit
            if price < min_price:
                min_price = price
        return max_profit
```

- 第 3 行 `min_price = prices[0]` —— 历史最低价的初始值取第一天。不能初始化为 0：价格最小也是 0，若初始成 0，"今天价 − 0"会算出虚高利润。也别用 `float('inf')`——能行但没必要，prices 非空是约束保证的。
- 第 4 行 `max_profit = 0` —— 最大利润从 0 起步：一路下跌时答案就是 0（题面钦定不亏就返回 0），所以初始值 0 自带兜底。
- 第 5 行 `for price in prices[1:]:` —— 从第二天开始走。切片 `prices[1:]` 会复制一份，数据量大时用 `for i in range(1, len(prices))` 更省；两版都对。
- 第 6 行 `profit = price - min_price` —— 站在今天试着卖一次：今天价减"此前见过的最低价"就是今天卖的上限利润。**这行必须在更新 min_price 之前**：反过来先更新最低价，遇到新低那天会算出"今天买今天卖"的 0 利润甚至把自己当买点——虽然对答案影响不大，但"卖必须在未来"的语义就破了。
- 第 7-8 行 `if profit > max_profit: max_profit = profit` —— 今天卖的结果比历史最佳好，就刷新纪录。这个 if 里放 return 是经典错法——后面可能还有更好的，记录要继续滚。
- 第 9-10 行 `if price < min_price: min_price = price` —— 走完这天后，今天价刷新历史最低就记下来，供未来各天当"最佳买点"用。
- 第 12 行 `return max_profit` —— 在 for **外面**，整趟走完才交卷。
- 一句话总结：**两个 if 干两件事但只扫一遍**——先问"今天卖赚不赚"，再记"今天是不是新低"。顺序是先利润后最低价。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **min_price 初始化为 0**：现象——示例 1 返回 6（5-0 或 6-0 的虚高）。病因：价格 0 是"可能值"不是"哨兵"，min 初值必须是某个真实价格。修复：`min_price = prices[0]`。
2. **先更新最低价再算利润**：现象——一路下跌的数组（示例 2）偶尔仍对，但逻辑上会出现"同一天买卖"，某些输入出错。病因：更新顺序破坏"先买后卖"语义。修复：循环体内先算 profit、后更新 min_price。
3. **在利润刷新处直接 return**：现象——示例 1 返回 4（7→5 时就交卷）而不是 5。病因：最大值可能出现在后面。修复：只记录不返回，return 放循环外。
4. **暴力思路写超时**：现象——LC 上超时（Time Limit Exceeded）。病因：双循环所有买日×卖日配对是 O(n²)，n 最大 10⁵ 就是百亿级操作。修复：换历史最低价单趟法。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"想到遍历但不知道该记什么"——其实就两个数：历史最低 + 最大利润，很多人一上来想套哈希或双层循环。
2. 最容易漏的动作：先算利润再更新最低价的**顺序**，以及 max_profit 初始 0 的"不亏兜底"。
3. 为什么快：暴力枚举所有（买日，卖日）配对是 O(n²)，10⁵ 天就是约 50 亿次比较，直接超时；历史最低法一趟 O(n)。一句话：每天的卖法只需和"之前最低价"比，不用和之前每一天都比——历史最低价压缩了所有历史信息。
4. 信号词："只能买卖一次""最大差值""卖在买之后"→ 一次遍历记录历史最低；如果允许买卖多次是 LC122，思路升级成"把所有上涨段都吃下"。
5. 变式：可以多次买卖？（LC122，贪心，所有正差值累加。）最多交易两次？（LC123，进阶 DP，先跳过。）
</details>
