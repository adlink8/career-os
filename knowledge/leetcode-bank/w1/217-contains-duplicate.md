# LC217 存在重复元素（简单）

> 一句话考点：查"这个数见过没" | 模式：哈希（set/dict）

## 题面

给你一个整数数组 `nums`。如果任一值在数组中**至少出现两次**，返回 `true`；如果数组中每个元素**互不相同**，返回 `false`。

```text
示例 1：nums = [1,2,3,1]        → true
示例 2：nums = [1,2,3,4]        → false
示例 3：nums = [1,1,1,3,3,4,3,2,4,2] → true
```

约束：`1 <= nums.length <= 10^5`，`-10^9 <= nums[i] <= 10^9`。

```python
class Solution:
    def containsDuplicate(self, nums: list[int]) -> bool:
```

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. 造一个空袋子；
2. 逐个拿数组里的数；
3. 每拿一个，先问袋子"见过它吗"——见过，说明重复，直接交卷 true；
4. 没见过，把它放进袋子，继续；
5. 全部走完一次都没撞上，交卷 false。注意：交 false 的时机在循环**外面**——只有走完所有数，才有资格说"没有重复"。
</details>

1. 遍历什么：输入数组 nums，一个一个过。
2. 记录什么：一个 set，装"已经走过的数"。
3. 怎么判断/返回：当前数先查 set——查到就 return True；查不到才放进去。循环全部走完还没查到过，return False。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

**解法 A·草稿纸版（先掌握这个）**

```python
class Solution:
    def containsDuplicate(self, nums: list[int]) -> bool:
        seen = set()
        for i in nums:
            if i in seen:
                return True
            seen.add(i)
        return False
```

- 第 3 行 `seen = set()` —— 造一个空袋子，set 会自动去重，专门用来"记见过的数"。注意空集合必须写 `set()`，写 `{}` 得到的是字典。
- 第 4 行 `for i in nums:` —— 逐个数数组里的数，i 是当前这个数。
- 第 5 行 `if i in seen:` —— **先查**。set 的 `in` 是哈希直达（O(1)），不是从头翻页（那是列表的 in，O(n)）。
- 第 6 行 `return True` —— 查到了 = 这个数之前走过 = 重复，当场交卷。
- 第 7 行 `seen.add(i)` —— **后存**。查完没撞上，才把当前数放进袋子。这行如果写成 `seen = i`，等于把袋子扔了换成单个数字，下一轮 `i in seen` 直接报错——`=` 是"整个变量换内容"，不是"往容器里放东西"。
- 第 8 行 `return False` —— 在 for **外面**（缩进和 for 平齐）。只有全部数都走完、一次都没撞上，才有资格说"没有重复"。这行如果写进循环里，第一个数没撞上就交 false 了，后面真重复的数根本轮不到被查。

**解法 B·一行版（懂了 A 再看）**

```python
class Solution:
    def containsDuplicate(self, nums: list[int]) -> bool:
        return len(set(nums)) != len(nums)
```

- 逻辑：把整个数组丢给 set 自动去重——有重复则袋子变轻（长度变小）。变短了 = 有重复。
- 和解法 A 是同一个本质的两副面孔：都靠"重复会让集合比数组小"这个事实。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **`seen = i`（=覆盖容器）**：现象——第二轮报 `TypeError`。病因：`=` 是把变量整个换成新内容，不是放入。修复：放入用 `seen.add(i)`（set）或 `seen[i] = ...`（dict）。
2. **return False 写进循环**：现象——`[1,2,3,1]` 返回 false。病因：第一个数没撞上就下了"没有重复"的结论。修复：false 只能循环走完后返回。
3. **先存后查**：现象——任何数组都返回 true。病因：先把自己放进去再查，查到的"重复"是自己。修复：先查后存。
4. **`{}` 当空集合**：现象——能跑但语义错位，`{}` 是字典。修复：空集合写 `set()`。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"没想到用啥记录"——暴力解是每个数和其他所有数两两比（O(n²)），卡点在想不到"用空间记"。
2. 最容易漏的动作：先查后存的**顺序**（先存后查永远撞自己）。
3. 为什么快：暴力是每个数重扫全数组 O(n²)；set 把"查一次"从翻页 O(n) 变成哈希直达 O(1)，整体 O(n)。代价是袋子占内存——**空间换时间**。
4. 信号词："出现过两次""有没有重复""查见过没"→ 哈希。
5. 变式：找数组里唯一的那个数（其他都成对）？同一招反过来用。数出现超过 n/2 次？（169 多数元素，还是哈希计数。）
</details>
