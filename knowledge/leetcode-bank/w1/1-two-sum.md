# LC1 两数之和（简单）

> 一句话考点：查"和它凑成 target 的搭档见过没" | 模式：哈希（dict，先查后存）

## 题面

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出**和为目标值**的那**两个**整数，并返回它们的数组下标。你可以假设每种输入只会对应一个答案，并且你不能使用两次同样的元素。你可以按任意顺序返回答案。

```text
示例 1：nums = [2,7,11,15], target = 9  → [0,1]（nums[0] + nums[1] = 9）
示例 2：nums = [3,2,4],    target = 6  → [1,2]
示例 3：nums = [3,3],      target = 6  → [0,1]
```

约束：`2 <= nums.length <= 10^4`，`-10^9 <= nums[i] <= 10^9`，`-10^9 <= target <= 10^9`，只会存在一个有效答案。

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
```

<details><summary>💡 提示第 1 档·方向（点开前先自己想 3 分钟）</summary>

拿到一个数时，别盯着它自己找答案，问一句：**"谁能让它凑齐 target？"** 那个"搭档"要是之前出现过，你现在就该认出来——所以你需要一样东西，边走边**记住走过的数和它们的家（下标）**，并且能一问就答。注意这题不光要认出数，还要报出它的位置，所以草稿纸上不能只记数字，还得记地址。
</details>

<details><summary>💡 提示第 2 档·模式点名</summary>

用哈希家族的 dict（键值对柜子）当草稿纸：键放"走过的数"，值放"它的下标"。动作顺序还是那个本命：**先查，后存**。查的内容从"见过它吗"升级成"见过它的搭档吗"。
</details>

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. 造一个空柜子，以后每个格子写"数字 → 下标"；
2. 逐个数组里的数，每拿一个先算出它需要的搭档是多少（目标值减它）；
3. 先问柜子："搭档之前来过吗？"——来过，把柜子里记的那个下标和当前下标打包交卷，完事；
4. 没来过，把当前数和它的下标写进柜子，继续；
5. 全走完还没配对，按题意不会发生（题目保证有答案），但保险起见返回空列表。顺序千万别反：先存后查会让一个数和它自己配对（示例 1 里 2+2≠9 没事，但 target=4 时 [2,...] 就会自己配自己）。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：输入数组 nums，带着下标一个一个过。
2. 记录什么：一个 dict，键是"走过的数"，值是"它的下标"。
3. 怎么判断/返回：当前数先算搭档（target 减它），查 dict——查到就 return [搭档的下标, 当前下标]；查不到才把当前数写进去。这题返回的是**两个下标**，不是 true/false。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        seen = {}
        for i, n in enumerate(nums):
            if target - n in seen:
                return [seen[target - n], i]
            seen[n] = i
        return []
```

- 第 3 行 `seen = {}` —— 造一个空柜子，键放数字、值放下标。这题必须用 dict 不能用 set，因为撞见搭档时还要报出"他当时站的位置"。
- 第 4 行 `for i, n in enumerate(nums):` —— 逐个数组里的数，`enumerate` 一次给两样：下标 i 和数值 n。只写 `for n in nums` 就丢了下标，最后没法交答卷。
- 第 5 行 `if target - n in seen:` —— **先查**。算出"我需要谁才能凑齐"，问柜子他来过没。dict 的 `in` 查的是键，哈希直达 O(1)。反过来先查 `n in seen`（查自己）就错了——自己刚要存进去，查到的永远是别人存过没，白查。
- 第 6 行 `return [seen[target - n], i]` —— 查到了，打包两个下标交卷：柜子里记的是搭档的下标，i 是当前数的下标。注意返回的是**列表里装两个整数**，不是 True 也不是数值本身。
- 第 7 行 `seen[n] = i` —— **后存**。查完没配对，才把当前数和位置写进柜子。这行如果挪到第 5 行前面（先存后查），一个数会和自己配对：target=6、数组 [3,2,4] 时，走到 3 先存，接着查 6-3=3，查到自己刚存的 3，返回 [0,0]——错。题目明说"不能使用两次同样的元素"。
- 第 8 行 `return []` —— 保险丝，题面保证有答案所以基本走不到，但函数写全返回值是好习惯。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **先存后查（自己配自己）**：现象——`[3,2,4], target=6` 返回 [0,0]。病因：把当前数存进柜子后才去查搭档，查到的"搭档"是它自己。修复：严格先查后存，查完没中才存。
2. **返回值搞错对象**：现象——`return [n, target-n]` 返回了两个数值。病因：题目要的是**下标**不是数。修复：返回 `seen[搭档], i`。
3. **只写 `for n in nums` 丢下标**：现象——最后返回不了位置。病因：遍历时只拿了数值没拿下标。修复：用 `enumerate(nums)` 同时拿 i 和 n。
4. **return 写进循环末尾兜底**：现象——没答案的输入死循环报错或漏返回。病因：以为循环里能处理一切。修复：循环外的返回写全。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"想到用 dict 但不知道键值各放啥"——键放数、值放下标，因为最后要交的是地址不是数。
2. 最容易漏的动作：先查后存的**顺序**（先存后查等于允许自己和自己组队）。
3. 为什么快：暴力是每个数和它后面所有数两两相加试错，O(n²)；dict 把"找搭档"从翻页 O(n) 变成哈希直达 O(1)，整体 O(n)。一句话：查搭档这件事从"重扫一遍"变成"问柜子"。
4. 信号词："两数之和""找搭档""返回下标"→ dict 先查后存（和 LC217 的区别：要存地址，set 升级成 dict）。
5. 变式：三数之和？（LC15，排序+双指针，不是套三层 dict。）数组有序找两数？（LC167 双指针，两头往中间夹。）
</details>
