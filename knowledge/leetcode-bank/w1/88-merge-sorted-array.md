# LC88 合并两个有序数组（简单）

> 一句话考点：两个排好队的箱子怎么并成一排还不打乱顺序 | 模式：双指针·从后往前填充

## 题面

给你两个按**非递减顺序**排列的整数数组 `nums1` 和 `nums2`，另有两个整数 `m` 和 `n`，分别表示 `nums1` 和 `nums2` 中的元素数目。请你**合并** `nums2` 到 `nums1` 中，使合并后的数组同样按非递减顺序排列。**注意**：最终合并后数组不应由函数返回，而是存储在数组 `nums1` 中。为了应对这种情况，`nums1` 的初始长度为 `m + n`，其中前 `m` 个元素表示应合并的元素，后 `n` 个元素为 `0`，应忽略。`nums2` 的长度为 `n`。

```text
示例 1：nums1 = [1,2,3,0,0,0], m = 3, nums2 = [2,5,6], n = 3 → [1,2,2,3,5,6]
示例 2：nums1 = [1], m = 1, nums2 = [], n = 0               → [1]
示例 3：nums1 = [0], m = 0, nums2 = [1], n = 1              → [1]
```

约束：`nums1.length == m + n`，`nums2.length == n`，`0 <= m, n <= 200`，`1 <= m + n <= 200`，`-10^9 <= nums1[i], nums2[j] <= 10^9`。

```python
class Solution:
    def merge(self, nums1: list[int], m: int, nums2: list[int], n: int) -> None:
```

<details><summary>💡 提示第 1 档·方向（点开前先自己想 3 分钟）</summary>

两排已排好的队要合成一排。最直觉是"从头比，小的先放"——但先想清楚：放的结果要写回 nums1，而 nums1 前段还站着没处理的元素，从头写会不会踩到还没搬走的人？再想一件事：nums1 的**尾巴**正好空着 n 个坑。谁比较大谁就该站在靠后的位置——**最大的东西先安顿，正好填最里面的空坑**，互不打架。
</details>

<details><summary>💡 提示第 2 档·模式点名</summary>

双指针合并，但方向反着来：一个指针看 nums1 的有效尾部，一个指针看 nums2 的尾部，再用一个"写指针"从 nums1 的最末尾往前填。三根指针，每次放当前最大的一方，写指针左移一格。
</details>

<details><summary>💡 提示第 3 档·步骤点破（卡死 15 分钟才许开）</summary>

1. 准备三根指针：i 指 nums1 有效部分的最后一位（m-1），j 指 nums2 的最后一位（n-1），p 指 nums1 真正的最后一位（m+n-1）；
2. 只要 nums2 还有没安顿完的（j 没走到底），循环：
3. 比 i 和 j 指的数谁大——i 还有效且 nums1[i] 更大，就把 nums1[i] 放到 p 的位置，i 左移；否则把 nums2[j] 放到 p 的位置，j 左移；
4. p 每放完一次就左移一格；
5. 循环结束后不用管 nums1 剩下的（它们本来就在前面对的位置上），交卷。
</details>

<details><summary>📝 三句口述参考</summary>

1. 遍历什么：不是从头到尾走数组，而是三根指针从右往左一起收缩。
2. 记录什么：i = nums1 有效区尾部，j = nums2 尾部，p = 填充位置（nums1 最末尾）。
3. 怎么判断/返回：每轮放"两指针中较大者"到 p，对应指针和 p 各左移；nums2 全部安顿完（j 走空）就结束，原地生效无需返回。
</details>

<details><summary>🔍 参考实现 + 逐行解析</summary>

```python
class Solution:
    def merge(self, nums1: list[int], m: int, nums2: list[int], n: int) -> None:
        i, j, p = m - 1, n - 1, m + n - 1
        while j >= 0:
            if i >= 0 and nums1[i] > nums2[j]:
                nums1[p] = nums1[i]
                i -= 1
            else:
                nums1[p] = nums2[j]
                j -= 1
            p -= 1
```

- 第 3 行 `i, j, p = m - 1, n - 1, m + n - 1` —— 三根指针各就各位：i 站 nums1 有效数据的最右，j 站 nums2 的最右，p 站 nums1 整条的最右（那是预留空位）。减 1 是因为下标从 0 数起，最后一个元素的下标是长度减一——这是本模式最常见的 off-by-one 雷。
- 第 4 行 `while j >= 0:` —— 只要 nums2 还有没安顿的就继续。循环条件选 j 而不是 i 或 p 是关键：**i 走空了不要紧**（nums1 剩下全在后面，nums2 接着填），j 走空了说明 nums2 全归位、nums1 剩的本来就在原地，直接收工。
- 第 5 行 `if i >= 0 and nums1[i] > nums2[j]:` —— 双重保险：先确认 nums1 还有有效数据可比（i >= 0），再比大小。`and` 短路保证 i 为 -1 时不会拿 `nums1[-1]` 出来比（Python 负下标不报错而是取末尾元素——**那才是更阴的坑**，逻辑悄悄错还不报异常）。
- 第 6-7 行 `nums1[p] = nums1[i]; i -= 1` —— nums1 尾部的大数放到 p 坑里，i 左移。从后往前填的底气就在这：p 永远 >= i + 1，写 p 不会踩到还没读的 nums1 有效数据。
- 第 8-10 行 `else: nums1[p] = nums2[j]; j -= 1` —— nums2 的大数（或 i 已走空）放 p 坑，j 左移。else 同时兜住"i 走空"的情况，此时 nums2 剩的全是较小的，依次填进去正好有序。
- 第 11 行 `p -= 1` —— 每安顿一个，坑位左移一格。忘了这行会反复覆盖同一个坑。
- 为什么从后往前而不是从前往后：从前往后放，`nums1[p] = ...` 会覆盖 nums1 前段还没处理的小数——那些 0 坑前面的真数据会被冲掉。从后往前，填的位置（尾巴空坑）永远不碰待读数据，零额外空间搞定。
</details>

<details><summary>🪤 常见坑（按杀伤力排序）</summary>

1. **从前往后覆盖真数据**：现象——示例 1 得到 [2,2,3,0,5,6] 之类。病因：从下标 0 开始放，把 nums1 未处理的元素冲掉了。修复：改从后往前，先用尾巴空坑。
2. **`nums1[-1]` 阴招**：现象——不报错但结果错。病因：i 变 -1 后 `nums1[i]` 在 Python 里取的是末尾元素，负下标合法但语义全错。修复：比较前先判 `i >= 0`。
3. **指针忘左移 / p 忘减**：现象——死循环或同坑覆盖。病因：安顿完数据没动指针。修复：每放一个，读指针和写指针各左移一次。
4. **以为要 return**：现象——写了 `return nums1` 但函数里 nums1 没改（用了 `nums1 = sorted(...)` 换盒子）。病因：`=` 是给变量换新内容，原数组没动。修复：必须原地写入 `nums1[p] = ...`，函数返回 None 是题面要求。
</details>

<details><summary>🎯 对账五问（做完再展开）</summary>

1. 第一个卡点通常在"三个指针初始位置"——m-1 / n-1 / m+n-1，三个减一漏一个就全盘错位。
2. 最容易漏的动作：循环条件用 `j >= 0` 而不是 `i >= 0`（条件选错，nums2 剩的数没搬完就收工）。
3. 为什么快：最朴素是"拼一起重新排序"O((m+n)log(m+n))；本解一趟双指针 O(m+n)。一句话：两个已经有序的部分，没必要付排序的 log 代价，顺序信息直接利用。
4. 信号词："两个有序""合并""原地写入"→ 双指针合并；看到"nums1 尾部有 0 空位"→ 从后往前填。
5. 变式：nums1 没有预留空位、要求返回新数组？（从头双指针 + 新数组，更简单。）合并 k 个有序数组？（进阶：逐个两两合并或用堆。）
</details>
