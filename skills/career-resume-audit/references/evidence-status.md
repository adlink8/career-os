# 证据状态五档与原子主张拆分

> 改编自 Claycui828/ASu-resume-skills `references/evidence-methodology.md`(自我审计场景化)。

## 原子主张拆分规则

一段简历经历至少包含四类独立主张,分开核验:

1. **角色主张**:"主导/Owner/核心/独立"——谁授予?边界在哪?
2. **范围主张**:"全链路/端到端/整体架构"——覆盖到哪一层?哪部分是别人的?
3. **结果主张**:数字本身——分子、分母、基线、时间窗口是否齐全?
4. **因果主张**:结果归因于"我"——排除团队/平台/趋势因素后还剩多少?

## 五档状态定义

| 状态 | 判定标准 | 简历处置 |
|------|----------|----------|
| `corroborated` | 有独立证据(公开仓库、在线服务、可复现数据)支撑主张的关键内容 | 保留原文 |
| `partially_corroborated` | 事实存在,但角色、范围、因果或幅度超出证据 | 收窄:降角色词、限定 Scope、补限定语 |
| `contradicted` | 可靠证据与主张直接冲突(如数字对不上、时间矛盾) | 必改,这是面试炸弹 |
| `unsupported` | 合理检索后无证据,但可能为真 | 补证据(补测数据/公开仓库)或删除 |
| `unverifiable` | 只有本人能讲,无公开可验证载体 | 移到面试口述,简历降权或不写 |

## 内部一致性检查清单(零外部依赖)

- [ ] 所有百分比能报出分子分母
- [ ] 日期线无冲突(在读期间全职实习?项目时间重叠?)
- [ ] "最/第一/唯一/核心"有明确比较集
- [ ] 项目整体指标 ≠ 个人指标(混用即降级)
- [ ] 技能分级与 profile.yml 三级一致(learning 不变熟练)
- [ ] 每个项目至少 1 条量化成果,且口径可解释

## 置信度与可改变条件

每条结论标 high/medium/low 置信度,并写明"什么证据出现会改变结论"——自我审计时这指导你补证据的优先级。
