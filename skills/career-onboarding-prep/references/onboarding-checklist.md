## 二、合同审查清单(签合同前必看)

### 试用期条款(最关键)

| 项目 | 法律规定 | 警惕信号 |
|------|---------|---------|
| 试用期长度 | 合同期<1年≤1月;1-3年≤2月;3年以上≤6月 | 超出法定上限 = 违法 |
| 试用期工资 | ≥转正工资的 80% | 低于 80% = 违法 |
| 试用期社保 | 必须缴纳 | "试用期不交社保" = 违法 |

### 其它重点条款

- [ ] 工作地点(是否可单方调整 → 风险)
- [ ] 岗位职责(是否与 offer/JD 一致)
- [ ] 竞业限制(范围/补偿/期限 → 离职后限制)
- [ ] 保密协议(范围/期限)
- [ ] 培训违约金(如有培训,违约金条款)
- [ ] 解除条件(双方提前多少天通知)

### 红旗(出现就别签)

- 要求交押金/培训费/服装费(违法)
- 扣押身份证/毕业证(违法)
- 试用期不签合同(违法)
- 合同空白处让你先签(风险)

## 三、Day 1 报到清单

### 必带物品

- [ ] 身份证(原件 + 复印件 2 份)
- [ ] 学历证明(原件 + 复印件)
- [ ] 银行卡(确认是否指定银行)
- [ ] 体检报告(如公司要求)
- [ ] 离职证明(如有前工作)
- [ ] 照片(1寸/2寸各 4 张)
- [ ] 笔 + 本子(记录用)

### Day 1 流程

```
上午:
├── HR 处:提交材料 + 签合同 + 录指纹
├── IT 处:领电脑 + 申请账号
└── 部门:见领导 + mentor + 同事

下午:
├── 配置开发机(装系统/软件/环境)
├── 读新人文档(如有)
└── 熟悉办公区(洗手间/茶水间/会议室)
```

## 五、30/60/90 天检查点

### Day 30 检查点

```
✅ 能独立完成常规任务
✅ 知道遇到不同问题找谁
✅ 融入团队(被叫去吃饭/参与闲聊)

如果达不到:
├── 主动找 mentor 沟通困难
├── 调整学习方法(可能方向错了)
└── 不要藏着,越早暴露越好
```

### Day 60 检查点

```
✅ 能独立 owner 一个任务
✅ 主动提出过改进建议
✅ 开始有"自己的判断"

如果达不到:
├── 检查是否被分配了过难的任务
├── 检查是否主动争取机会
└── 与领导 1v1 沟通期望
```

### Day 90 检查点(转正)

```
✅ 有可量化的成果(性能提升 X% / 处理故障 Y 次)
✅ 获得转正
✅ 清楚下一阶段目标

转正述职准备:
├── 整理 90 天工作成果(量化)
├── 准备 STAR 案例化呈现
├── 收集同事/领导正向反馈
└── 明确后续 3-6 个月发展
```

## 六、用户专属建议(基于 profile.yml)

### 用户岗位:运维/技术支持

重点参考 `knowledge/onboarding/new-ops-engineer-onboarding.md`:
- 运维三大铁律(生产先问后做 / 权限责任 / 不懂就问)
- 安全操作分级(可独立 / 需确认 / 绝对不能)

### 用户优势发挥

- **Python 熟练** → 运维岗稀缺,主动提议写自动化脚本
- **AWS IoT 项目** → 展示完整链路经验,快速建立信任
- **竞赛排障经验** → 展示故障排查思维

### 用户需注意

- **专升本背景** → 可能在某些公司被偏见,用成果说话
- **无生产环境经验** → 第一周多观察,不急于操作生产
- **第一份工作** → 至少做满 1 年攒经验,不急于跳槽
