# 简历钩子设计(主钩 / 次钩 / 兜底)

简历 bullet 不只是成绩陈述,还是面试提问的诱饵:面试官第一问几乎必然来自项目区第一条 bullet。写什么,决定他从哪里开始问。

## 前提:每条钩子必须扛住三层拷打

写之前逐条自问(答不上就降级写法或删除,钩子是借力不是赌博):

1. **是什么**——技术点能自己复述架构吗
2. **为什么**——当时的取舍记不记得(为什么 A 而非 B)
3. **踩坑**——有没有"只有做过才知道"的细节

三层都答得上 → 放心写并留钩子;只答得上一层 → 淡化或删,写上去是给自己埋雷。

## 每个项目 3 条 bullet 的分工

| 位置 | 功能 | 要求 |
|------|------|------|
| 主钩(第 1 条) | 决定面试开场方向 | 放存货最深的故事,故意留一个值得追问的点 |
| 次钩(第 2 条) | 面试官跳过第一条时的第二准备区 | 同样留钩,深度次之 |
| 兜底(第 3 条) | 防冷场 + 喘息 | 平铺直叙的技术广度陈述,不设钩 |

## 四种钩子写法

1. **反常细节钩**——写"正常剧本的例外",给名词不给解释。
   平:"建立 CI 流水线" → 钩:"含依赖漏洞无官方修复版时的显式豁免与解除机制"
2. **数字钩**——写精确但不自明的数字,数字本身就是问题。
   平:"做了质量检查" → 钩:"四轮随机抽检审计,定位系统性数据质量问题"
3. **名词钩**——用项目自有的设计名词,面试官要懂就必须问。
   例:"知识/叙事双单元混合检索" "ci-gate 分支保护"
4. **权衡钩**——写"A 而非 B",暗示做过选型。
   例:"以 ChromaDB 分层集合实现按项目隔离,而非全局单库"

## 被动型候选人的节奏原理

主导节奏 ≠ 主动引导,而是"每个回答末尾自然携带下一问的入口":

- 回答 = 直接答案 + 一句"当时的背景/为什么"
- 回答封闭(说完就停) → 面试官只好自己去简历别处找问题,问到你没准备的地方
- 回答开放(带上背景) → 他的每个问题都从你上一句长出来,链条永远在你手里

## 钩子落空预案

面试官不咬钩、直问兜底条时:一句话承认广度 + 主动引回主钩。

> "这块没什么特别的,倒是 XX 那个问题比较有意思,当时……"

## 反 AI 感约束

钩子密度受数字口径约束:每页可见数字 ≤5 个、取整、可点开验证(详见 career-resume-audit 的 `references/ai-flavor-patterns.md`)。钩子来自细节与决策,不来自堆数字。
