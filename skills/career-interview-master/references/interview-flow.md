## 二、面试环节标准流程(用户参照)

### 一面(技术面,通常 45-60 分钟)

```
1. 自我介绍(2-3 分钟)
   ↓
2. 项目深挖(15-20 分钟,核心)
   - 面试官挑简历项目问细节
   - 必须能讲清:做了什么 + 怎么做 + 结果
   ↓
3. 技术问答(15-20 分钟)
   - 基础概念(Linux/网络/Docker)
   - 场景题(故障排查、设计)
   ↓
4. 反向提问(5-10 分钟)
   - 必问!不问 = 减分
```

### 二面(资深/主管面,通常 45-60 分钟)

```
1. 项目更深挖(架构/权衡/为什么这么选)
2. 系统设计题(初级运维较少,但可能问)
3. 行为面(团队协作/抗压/职业规划)
4. 反向提问
```

### HR 面(通常 20-30 分钟)

```
1. 基本情况确认
2. 求职动机(为什么选我们/这个岗位)
3. 职业规划(3-5 年)
4. 薪资期望(转谈薪模块)
5. offer 时间线/竞品
6. 反向提问
```

## 三、评分标准(各维度细则)

### 技术准确性(40%)

| 分数 | 标准 |
|------|------|
| 5 | 概念精准、能讲深度、能延伸 |
| 4 | 概念正确、有基本深度 |
| 3 | 概念大体对、有少量偏差 |
| 2 | 概念模糊、有明显错误 |
| 1 | 完全不会 |

### 表达清晰度(30%)

| 分数 | 标准 |
|------|------|
| 5 | 有条理(分点)、简洁、重点突出 |
| 4 | 基本清晰、偶有啰嗦 |
| 3 | 能讲出来、但逻辑不够顺 |
| 2 | 啰嗦/跑题/答非所问 |
| 1 | 讲不清 |

### 项目结合度(20%)

| 分数 | 标准 |
|------|------|
| 5 | 主动用项目佐证、有量化数据 |
| 4 | 被问时能结合项目 |
| 3 | 偶尔提项目、但不够具体 |
| 2 | 几乎不结合项目 |
| 1 | 项目讲不清 |

### 追问应对(10%)

| 分数 | 标准 |
|------|------|
| 5 | 追问时能深入、不慌 |
| 4 | 追问能答、偶尔卡壳 |
| 3 | 追问时需要提示 |
| 2 | 追问就懵 |
| 1 | 完全答不上 |

## 四、常见面试官套路识别

### 套路 1:压力面试

- **表现**:故意质疑/打断/否定
- **应对**:不慌、不辩解、虚心听、理性回应
- **话术**:"您说的有道理,我之前的理解是 X,可能不全面,能否指点?"

### 套路 2:挖坑题

- **表现**:问"如果薪资比你预期低怎么办""你最大的缺点"
- **应对**:准备标准答案,不要掉坑
- **缺点题**答法:说一个真实但可控的缺点 + 正在改进的行动

### 套路 3:沉默施压

- **表现**:你答完后面试官沉默不说话
- **应对**:不要为了打破沉默乱补充,可以问"需要我补充什么吗?"

### 套路 4:诱导错误

- **表现**:故意给错误引导"是不是因为 X?"
- **应对**:坚持自己的判断,不盲从,礼貌说"我的理解是 Y,因为..."

## 五、面试后跟进(用户参照)

### 面试后 24 小时内

- [ ] 整理面试官提到的问题(为复盘准备)
- [ ] 记录面试官姓名/联系方式(如有)
- [ ] 在 tracker.tsv 更新状态(转 career-app-tracker)

### 面试后 3-5 天无反馈

- [ ] 主动跟进(通过 HR)
- [ ] 话术:"您好,X 天前面试了 {岗位},想了解后续进度"

### 面试挂了

- [ ] 复盘(模块三)
- [ ] 记录这次的问题(下次同类公司会问)
- [ ] 不要纠结,投入下一个

## 六、谈薪与 Offer 时间线

### 标准时间线(用户参照)

```
面试通过
  ↓ 1-3 天
HR 电话沟通意向 + 问期望薪资
  ↓ 1-5 天
口头 offer(谈薪黄金窗口)
  ↓ 1-3 天
书面 offer 发放
  ↓ 通常 3-7 天有效期
决定接/拒/谈
```

### 谈薪时机

- **最佳**:拿到口头 offer 后、书面 offer 前(筹码最强)
- **次佳**:书面 offer 发放后、有效期内
- **最差**:面试中被问期望(姿态弱,只能给区间)

详见 `knowledge/salary-data/negotiation-scripts.md`。
