# 每日作战台规范

优先级：已约面/笔试准备 > 已投递跟进 > 高匹配候选岗位核验 > 学习补缺。

统计规则：

- `已投递`、`初筛通过`、`测评已完成`、`笔试邀请`、`面试邀请`、`Offer` 才进入真实转化统计；
- `待投递`、`重点关注/待投递`、`待沟通内推` 只算候选，不算投递；
- 每项行动必须能在 `jobs` / `applications` 表或 `data/current-status.md` 中找到回写位置。

口径说明（2026-09-17 更新）：投递数据的唯一事实源是 `data/career_jobs.sqlite`。原 `tracker.tsv` 已废弃并删除——它与库并行且无写入方，已实测漂移（浩鲸交付岗库内"测评已完成"、TSV 仍"已投递"）。统计一律从库取：

```bash
python bin/career_jobs_cli.py track   # 转化管线看板
python bin/career_jobs_cli.py list    # 全量岗位与状态
```

`jobs.status` 与 `applications.status` 不一致时，先报不一致并列出冲突岗位，不要静默取其中一个。

## 🎯 投递节奏与质量管制（反海投铁律，2026-09-08 惨痛复盘固化）

1. **绝对禁令：严禁追量陷阱与一套多塞**
   - 严禁同一天拿 1~3 套简历在同一家或多家企业硬塞 8~10 个跨方向岗位。
   - 复合求职意向（如“AI与交付”）与弱对位简历在 ATS 跑分与 HR 初筛中必遭秒刷，属无效投递与自我感动。

2. **投递节奏（不写死每日家数）**
   - 每天投几家由用户当场决定。每家仍只投 1 个同方向岗。
   - **专投**：走编排器全流程（ATS≥70 + 会审）。
   - **海投**：用现用母版 ops / iot / semi，求职意向改成官网全称，**不**为每岗重写项目（方向差太远才改）。
   - 禁止：同一家硬塞多个跨方向岗、复合意向、测一填进真表。

3. **专投 20 分钟定制闭环（仅 precision 模式强制）**
   - **读靶（5 分钟）**：拆解目标 JD 前 3 大硬技能与 2 大业务场景词；
   - **校准（10 分钟）**：针对岗位深度调整**项目正文**（严禁只在技能栏口头吹水，核心词必须在项目正文中带动作落地；第一项目必须直击岗位业务，坚决剔除无关方向内容）；
   - **验靶（3 分钟·强制门禁）**：运行 `python bin/ats_matcher.py --job-id <ID> --resume <PDF路径>`。系统严格执行五维严苛检查（意向上限5分/项目对位40分），**必须评分 ≥ 70 分且无一票否决项方准放行**；
   - **击发（2 分钟）**：求职意向 100% 对齐官网 JD 全称（绝无复合词），使用 `python bin/career_jobs_cli.py apply <ID> --resume <PDF路径>` 经过门禁核验后写入投递流水线。
