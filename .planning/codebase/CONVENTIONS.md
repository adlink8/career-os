# 编码规范

> Generated by GSD `map` on 2026-06-28. 提炼自 10 个 skill + knowledge 的实际写法。

## SKILL.md 规范(强约定)

### frontmatter(字段顺序固定)

```yaml
---
name: career-<kebab-case>          # 必须与目录名一致,统一 career- 前缀
displayName: <4-6字中文名>          # skill 展示名
version: 1.0.0                     # 固定
agent_created: true                # 固定
description: >-                    # 多行折叠,2-3 句:做什么+手段+输出
  {场景}。{手段},输出{交付物},{避免的负面}。
trigger:                           # 数组,固定 3 行:动作词/术语/痛点
  - {动作词} / {同义词} / ...
  - {术语} / {术语} / ...
  - {痛点原话} / {痛点} / ...
---
```

### 正文骨架(顺序固定)

```markdown
# {displayName} ({PascalCase 英文})

你是{角色}。{一句价值主张 / 边界声明}。

## 运行规则
### 启动时读取 / 必须读取 / 数据来源
1. `config/profile.yml` — {读取目的}
2. `knowledge/{子目录}/` — {读取目的}

## 模块一:{动词+对象}
## 模块二:{核心处理}
## 模块三:{深化/输出}
## 模块四:{收尾/策略}

## 输出规范      ← 3-5 条 bullet,含禁区(不用"亲"/"加油")
## 参考文档      ← 2 条:`references/xxx.md` + `knowledge/xxx/`
```

### 命名约定

| 对象 | 规则 | 示例 |
|------|------|------|
| skill 目录 | `career-<kebab-case>` | `career-general-recruit` |
| reference 文件 | `<kebab-case>.md`,描述性强 | `recruit-workflow.md` |
| knowledge 域 | `<kebab-case>/`,复数或领域名 | `assessment-banks/` |
| 知识文件 | `<kebab-case>.md` | `aptitude-strategies.md` |

## 路径引用规范

| 路径类型 | 写法 | 物理位置 |
|---------|------|---------|
| 项目级共享 | `` `config/profile.yml` `` `` `data/tracker.tsv` `` `` `knowledge/<域>/` `` | 项目根 |
| skill 私有 | `` `references/<file>.md` `` | 各 skill 自己子目录内 |
| **所有路径从项目根写起** | 反引号包裹 | — |

## Markdown 风格

- 输出模板用 ```` ``` ```` 代码块,内含 `{占位符}`
- 结构化输出用 ASCII 树 `├── └──`
- 映射关系用 Markdown 表格
- 章节标题中文冒号:`## 模块一:xxx`

## 数据文件规范

### profile.yml 三级技能

```yaml
skills:
  proficient:   # 熟练:能独立完成 + 能教别人 + 能排查
  familiar:     # 掌握:看得懂 + 能改 + 知道在哪查
  learning:     # 学习中:知道是什么 + 在学 + 没独立用过
```
判定标准见 `knowledge/self-assessment/skill-stack-grading.md`。

### tracker.tsv 8 列契约

`日期 公司 岗位 城市 薪资范围 平台 状态 备注` — 见 `references/tracker-spec.md`。

### 模板占位符

真实数据文件用 `{{变量名}}`(双花括号),如 `templates/cv-template.md`。
真实数据存 `data/cv/cv-real.md` / `config/profile.yml`(均 gitignored)。

## 验证脚本规范(PowerShell)

- 零外部依赖(纯内置 cmdlet)
- 中文输出 + 彩色(PASS 绿/FAIL 红/WARN 黄)
- exit code:0=clean,1=drift(供 CI 或自动化判断)
- skill 列表硬编码在脚本顶部数组,新增 skill 需同步更新

## 文档真实性原则(最重要)

- **所有"完成度"声称必须可由 audit.ps1 复现**
- 不允许 README 写"已完成"而文件不存在(Phase 1 已修正)
- 知识层数据带 `📅 数据时效` 标签的,使用前必须 WebSearch 刷新(KNOW-03)
